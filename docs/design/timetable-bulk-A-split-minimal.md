# 周期排课 /timetable/bulk —— 方向 A：两个工具彻底分开 + 极简呈现

> 设计文档（**不含代码补丁**）。作者：设计子代理 A。日期：2026-10-04。
> 配套：量化基线 [timetable-bulk-baseline.md](timetable-bulk-baseline.md)（队长）。本文全程沿用它的读数口径，并给出我的独立复核。
> 用户原话：「周期排课的 UI 太乱了，能不能使用合适的技能整理整理优化一下。」

## 结论摘要（给队长 30 秒）

1. **两个工具两页**：/timetable/bulk 只做批量生成；「批量停用」搬到新页 /timetable/batch/deactivate（后台「时间表」菜单 + 排课页页脚一行链接），**不做 Tab** —— Tab 仍把 17 行表 + 14 个按钮塞进同一个页面（移动端实测该表 4113px，占整页 57%）。
2. **能删的说明全删**：规则搬进 placeholder / 字段标签 / 折叠摘要，只在「不写就会做错」处留字。小灰字 **79 → 约 11 处**（留下的都是「留空 = 一个课时长」这类 6~10 字的操作信息）。
3. **默认值变聪明**：起止日期按当前学期预填（本地实测：第一学期 2026-06-23 ~ 2026-12-20）⇒ 单班 / 每周 / 整学期的常见用法**只动 6 个下拉或勾选**即可提交。
4. **内部代号 17 → 0 处用户可见**（「（A123）」全部转 title 悬停）；行话「错开口径 / 合班批 / 循环方式 / 周次范围 / 推导 / 代号 / 冲突四查」全部改写。
5. **投影读数**（把静态布局原型注入真主题量出来的，**不是已落地功能**）：整页 **2290 → 约 1009px**；主操作 **1220 → 738px**（进首屏）；表单控件 40+6 → 15。落地后必须用同一把尺子复测（§6）。
6. **顺带发现两个既有缺陷**（与「乱」无关，但持续制造挫败）：① 服务端校验失败后**已填内容全部丢失**（可复现路径见附录 A-7）；② 页首提示仍在宣称「整周复制」，而 /timetable/copy **实测 404**（该功能 2026-09-15 已按用户裁定删除）。

## §1 信息架构（IA）

### 1.1 为什么是「两页 + 一个次级入口」，而不是 Tab

| 方案 | 首屏负担 | 发现性 | 两工具是否一眼可分 | 判定 |
|---|---|---|---|---|
| A1 同页上下排（现状） | 17 行表 + 14 按钮常驻 | 高 | 否，只隔一条细线 | 淘汰 |
| A2 两个 Tab | **一样重**：Tab 只是视觉隐藏，DOM 与渲染成本还在；且 Tab 暗示「同一任务的两种看法」 | 高 | 一般 | 淘汰 |
| A3 停用降级为生成页的次级入口（页脚/折叠） | 轻 | 中 | 是 | **采纳：页脚一行链接** |
| A4 停用独立成页（新区 + 后台菜单项） | 轻 | 中（菜单 + 页脚双入口补偿） | 是 | **采纳** |

**决策 = A3 + A4 合体**：生成页保留头牌 URL /timetable/bulk；停用列表新开 /timetable/batch/deactivate，同时挂后台「时间表」菜单（与现有「周期排课（批量）」「停课管理」同级，写法抄 views/menu.xml:11-22）。理由是这两个工具的**使用节奏不同**：排课是每周/每学期的常规动作，停用是「班级组成改过之后的一次性纠错」；把纠错工具放进常规流程的首屏，等于每次排课都先读一遍纠错说明书。

### 1.2 页 A：/timetable/bulk「周期排课」区块表

| # | 区块 | 内容 | 默认 |
|---|---|---|---|
| 1 | 面包屑 + 标题 | 「周期排课」+ 副题「填好 → 预览 → 确认生成。确认前不会写入任何课节。」+ 右侧静态步进条「1 填表 · 2 预览 · 3 生成」 | 展开 |
| 2 | 停课日提示 | 1 行：「停课日 1 个：2026-10-01 中秋（生成时自动跳过）」；details 内放全部停课日 + 「在后台维护」 | **折叠**（只 1 行） |
| 3 | 主卡片 · 组①「给谁排、排什么」 | 班级＊（单选下拉）｜课程＊（下拉 + 或新建）｜科目＊（下拉 + 或新建）｜教师＊ | 展开 |
| 3a | 组① 下方 · 多班 | details「还要给别的班一起排（时间自动错开）」：班级勾选（普通班在前、合班在后）+「每班顺延」 | **折叠** |
| 4 | 主卡片 · 组②「什么时候」 | 星期几＊（7 个 chip）｜上课时间＊（下拉）｜起止日期＊（两框一行，预填学期） | 展开 |
| 4a | 组② 下方 · 自己填时间 | details「没有合适的节次？自己填时间」：两个 time 输入 | **折叠** |
| 4b | 组② 下方 · 高级 | details「少数情况：只排部分周 / 单周或双周」：周次范围 + 频率（每周/单周/双周） | **折叠** |
| 5 | 主卡片 · 组③「在哪」 | 教室（首项「— 不指定 —」） | 展开 |
| 6 | 动作条 | 主按钮「预览将生成的课节」+ 一行「有冲突的课节不会被创建，预览里会逐条说明」 | 展开 |
| 7 | 页脚次要区 | 「其他工具：批量停用某班的全部课时」｜「只想改一节？在后台「时间表」里直接改删」 | 展开（弱化） |

（＊ = 必填。全文用 ＊ 表示星号，避免与 Markdown 强调符冲突。）

原则：**一字段一控件**。现状「课程」= 下拉 + 小输入两条控件，「上课时间」= 下拉 + 两个 time + 夹一个「或自定义」，全部收成「一条主控件 + 一个折叠的第二形态」。
必填 6 项：班级、课程、科目、教师、星期几、上课时间；日期已预填 ⇒ **常见用法只动 6 下**。

### 1.3 页 B：/timetable/batch/deactivate「批量停用课时」（新）

| # | 区块 | 内容 | 默认 |
|---|---|---|---|
| 1 | 标题 + 一句话 | 「批量停用课时」+「停用 = 状态改成「停课」，记录不删、可随时改回；学生和老师的课表马上不再显示。」 | 展开 |
| 2 | 卡片：「有在用课时的班级（14）」 | 表：班级（+「合班」badge）｜在用课时｜已停用｜「停用…」按钮；拼音序；**代号进 title**；**删除「推导组成」列** | 展开 |
| 3 | 折叠：「没有在用课时的班级（3）」 | 一行 muted 文字，**无按钮** | **折叠** |
| 4 | 每行「停用…」 | → 既有二次确认页（结构不动，只改文案） | — |

从列表里拿掉两列是**有意的**：
- 「代号」是给数据库看的（A123 / B1234），用户认的是班名；
- 「推导组成（需人工确认）」是 9 行重复的同一句免责声明，而**它真正生效的地方是确认页**（templates.xml:984-993 已在那页显示）。把「推导不等于事实」的确认放在即将动手的那一屏，比在列表里重复 9 遍更有用，也更少误导（列表阶段用户还没决定停哪个班）。

### 1.4 下游两页在 IA 里的位置

- **预览页**（已有 /timetable/bulk/preview）= 步进条第 2 步。结构保留（要素区 / 每周一览 / 明细折叠 / 冲突明细卡 / 确认生成），只做文案与链接修正。
- **停用确认页**（已有 /timetable/batch/<id>/deactivate）= 页 B 的下一步。结构保留（三张影响面卡 / 科目分布 / 受影响的人 / 勾选二次确认），只改文案与「返回」落点。

## §2 交互流程

### 2.1 三步（每步的主操作都在首屏）

~~~
第 1 步  填表（/timetable/bulk）            主按钮「预览将生成的课节」
   |  POST /timetable/bulk/preview（不落库；契约不变）
第 2 步  预览（/timetable/bulk/preview）     主按钮「确认生成（共 N 节）」+「返回修改」（带参数回填）
   |  POST /timetable/bulk/create（契约不变）
第 3 步  结果（303 回 /timetable/bulk?created=…）  绿条 +「查看课表」/「再排一门」
~~~

进度感来自**页头静态步进条**（第 1/2/3 步高亮），不是假计数：不显示「将生成 N 节」这类前端估算 —— 节数由服务端的周次、单双周、停课日、冲突共同决定（main.py:437-516），前端再算一遍必然与服务端不一致，属于「另造第二套判据」。

### 2.2 校验与反馈落点

| 校验 | 位置 | 现状 | 设计后 |
|---|---|---|---|
| 必填（日期、教师） | 浏览器原生 required | 原生气泡，**先于**服务端拦截（实测：缺日期时 POST 根本没发出） | **保留**（即时、不丢输入、不耗一次往返）。气泡语言随**浏览器界面语言**，不是页面缺陷 |
| 缺课程/班级/科目/教师/节次/日期跨度/星期几 | 服务端 error 字符串 | 红条渲染在**表单卡片之外**（y=274），且**已填内容全部清空**（实测） | 红条移到主卡片顶部（字段网格正上方）+ **回填已填参数**（见 §5 控制器 3/4）；文案本身已是中文人话，不改 |
| 时间冲突 | 预览页 | 红格 + 冲突明细卡 + 整批拒绝红条（契约要求保留可见） | **保留结构不变**；只换内部词：「冲突四查」→「时间冲突检查」，「重叠维度」→「冲突原因」 |
| 停课日 | 填表页 / 预览页 | 填表页黄条列出全部日期 | 收成 1 行，明细进折叠；预览页要素区保留 holiday 那句 |
| 生成结果 | 303 回填表页 | 绿条「成功生成 N 节课」 | 绿条 + 两个出口（查看课表 / 再排一门）；步进条标到第 3 步 |
| 停用二次确认 | 确认页 → 服务端判据 | 未勾选直接 303 回本页带中文原因（main.py:862-865） | **一行不改**（契约） |

### 2.3 三个关键状态

1. **首次进页**：首屏只有 12 个控件、6 个必填、1 个主按钮、3 个折叠摘要（其中只有「多班」「高级」与老用户相关）。日期已按当前学期预填。
2. **有冲突时**：第 1 步不预告，第 2 步如实呈现（红格 + 明细 + 整批取消）。第 1 步只在按钮旁留一句「有冲突的课节不会被创建，预览里会逐条说明」—— 这是「不写就会做错」的信息（用户以为能硬排进去），留。
3. **改一个数字重试**：预览页「返回修改」必须**带回全部参数**（现状是回到空白表单，等于重填 12 项）。这是本方向里唯一的「新增能力」，也是最值钱的一处：预览页模板手上已有全部 params（templates.xml:537-561），只是填表页不读回。

## §4 取舍

### 牺牲了什么

1. **发现性**：停用工具从「进页面必见」变成「后台菜单 + 页脚一行」。第一次找它的人可能要多看一眼。补偿：菜单项与页脚链接两处入口 + 发布说明一句话。
2. **常驻规则变少**：删掉的说明里有 3 条是真规则（填 0 的后果、一刻钟对齐、周次锚点全口径）。少数人会先踩一次再看到（兜底：预览页 + 服务端中文错误 + 停课日提示）。这是「极简」必须缴的税。
3. **两次额外点击**：多班排课、高级（周次/单双周）各进一层折叠 —— 对**老用户**是净增点击，对**首次使用者**是净减噪音。
4. **停用列表不再自证合班组成**（删「推导组成」列）⇒ 想知道推导组成必须点进确认页。有意为之：推导不是事实，放在要动手的那一刻读。
5. **两套校验语汇并存**：浏览器原生气泡 + 页面红条。之所以保留原生 required，是因为服务端报错会清空输入（现状），在回填修复落地前它反而是保护。
6. **契约不动带来的 UI 妥协**：batch_id（单班）与 batch_ids（多班）是两条服务端路径，预览页因此仍有两套版式（单班要素区 / 多班分班表）。UI 上「班级 + 折叠多班」看起来是一件事，服务端仍是分叉的 —— 这是「不改后端契约」买来的。
7. **预填日期是善意的猜测**：若学期数据不对，用户可能按错范围生成（兜底：预览页要素区显示「日期范围」，填表页预填行标注「已按第一学期预填」，改一下日期成本极低）。
8. **不做 sticky 动作条**（默认态已在首屏）。极端情形：三个折叠全展开时，投影主按钮落到 930px（比 900 首屏低 30px）。可选补丁：动作条 position: sticky; bottom: 0（约 3 行 CSS，需给模块加 assets 段）；代价是可能与页脚叠压，建议只在 <992px 启用。

### 换来了什么（都有读数或判据）

| 项 | 改前（实测） | 设计后（投影 / 判据） |
|---|---|---|
| 两个工具同屏 | 是（一条细线相隔） | **否**（两页；页 A 页脚一行链接） |
| 整页高度（1440 桌面） | 2290 px | **约 1009 px**（原型读数） |

| 小灰字 | 79 处 | **约 11 处**（基线目标 ≤30） |
| 内部代号（用户可见） | 17 处 | **0 处**（tooltip 兜底） |
| 行话 | 错开口径 / 合班批 / 循环方式 / 周次范围 | **0 处** |

## 附：与另外两个方向的边界（便于队长合并）

- 本方向**不碰**：edu_portal 的 ux3-* 样式（门户学生侧另一套视觉语言，且 edu_schedule 不能依赖 edu_portal，会成环）；/timetable/session/<id>/impact（改课影响面页）的结构；后台时间表的其他菜单。
- 本方向**可被别方向复用**的结论：.btn-check chip 的实测（A-8）；「服务端报错清空输入」缺陷（A-7）；「返回修改丢参数」缺陷；/timetable/copy 过时文案；以及「一条规则只在一处出现」的文案纪律。
