## 二之补：两条**与视觉无关**的缺陷（都已亲自复现，另行派修）

**① 服务端校验失败 ⇒ 整张表单被清空**（高影响）：

```
填齐 course_id=13 / batch_id / subject_id / faculty_id / timing_id + start_date/end_date
故意不勾「星期几」→ 提交 /timetable/bulk/preview
提示「请至少勾选一个星期几」✓（提示是对的）
但 8 个字段**全部变空** ⇒ 用户白填 12+ 个字段
```

⚠ 一个细节：设计子代理说「模板 input 无 `t-att-value`」—— **不准确**，模板里有 **42 处**。
但它的**观测**是对的（字段确实被清空）⇒ 解释错、结论对。修的时候以「实测字段是否保留」为准。

**② 页头还在宣传已被删除的功能**：`templates.xml:25` 写「本工具只负责批量生成与**整周复制**」，
而 `/timetable/copy` 已于 **2026-09-15 按用户裁定删除**（`docs/code-map.md:125`）。预览页也带着它。

⚠ **量具自己先出过一次错**：第一版用**半角**括号正则数内部代号，得到 **0 处** —— 而截图里明明有。
页面用的是**全角**「（A123）」⇒ 改成全角后是 **17 处**。
（同一天我已经被自己的量具骗过一次：第 106 轮把搜索页**回显的查询词**当成了命中。）
⇒ 记一笔：**报「0 处」时先怀疑量具，再相信结论。**

## 二、结构性问题（截图 + DOM 复核）

1. **两个不相干的工具挤在一页**：「周期排课（批量生成）」与「批量停用某班/合班批的全部课时」，中间只有一条细线；
2. **说明文字淹没控件**：79 处小灰字，例如「留空最省事（= 首班时长）；填 0 = 所有班同一时间（冲突预检会挡下并说明原因）」；
3. **18 个班级复选框 + 17 处内部代号**（`（A123）` `（A123B234）` `（B1-B4全体）`）—— 内部编码直接给人看；
4. **停用表 20 行、每行一个「停用…」按钮** + 一排「推导组成」徽章 + 10 处「（推导，需人工确认）」；
5. **「上课时间*（二选一）」**把下拉与两个自定义时间框挤在同一框里，中间夹「或自定义」；
6. **主操作在最底下**（1220 px 处，不在首屏）；
7. **行话**：「错开口径」「合班批」「循环方式」「周次范围」。

## 三、改完后的目标（可判定，不靠感觉）

| 指标 | 目标 |
|---|---|
| 主操作是否在首屏 | **是**（≤1000 px，或改成引导式后每一步的主操作都在首屏） |
| 小灰字 | **≤ 30 处**（79 → 降 6 成以上） |
| 内部代号 | **0 处**（可移到 tooltip / 次要位置） |
| 内部行话 | **0 处** |
| 「批量生成」与「批量停用」 | **不再同屏混排**（分页 / 分 Tab / 分步 皆可，但要一眼看出是两个工具） |
| 功能 | **一个都不能少**（逐条对照：字段、校验、预览、冲突预检、二次确认） |
| 门禁 | `check_all --fresh-install` 全绿；无障碍不得新增违规 |
