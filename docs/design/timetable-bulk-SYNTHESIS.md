## 二、各自的独有贡献（综合时都要留下）

**A 独有**：
- 可直接看的**布局原型**（`timetable-bulk-A/a2-wizard.png`），且**实测投影**整页 2290 → **~1009px**、主操作 1220 → **738px**；
- **零新增 CSS/JS**（`details/summary` + Bootstrap 5 `.btn-check` chip，且**实测**了勾选底色与焦点环）；
- 星期几从 18 个复选框变成 **chip**；三类杂项收进 `▶` 折叠；
- 淘汰「同页 Tab」的**实测理由**（客户端 Tab 仍把 17 行表留在 DOM）—— ⚠ 注意：C 用的是**服务端** `?tool=`，不适用此反驳。

**B 独有**：
- **55 / 79 处小灰字属于停用卡**、停用卡 763px ⇒ 「**先做这一刀**」的量化依据；
- **48 条文案逐条对照表**（原句带行号 → 新句 → 落点），可直接拿来改；
- **零 JS、零新路由**的分步法（`formaction="/timetable/bulk?step=2"`，提交目标与字段名逐字不变）；
- 指出**17 个班名里有 9 个自带代号**（`A123+B1合班`）⇒ 「内部代号 0 处」在**呈现层可达 0，数据层不可达**。

**C 独有（两条最重要）**：
- **「右栏永远不许出现『无冲突』」** —— 冲突依赖服务端 `_occupied_map()` 全表扫描，客户端拿不到也不该拿到；
  状态机只有「**还没查** → 已查」两态。理由一句话：**画个绿色对勾，用户就会跳过预览页 —— 而预览页是唯一一次真检查。**
  这是三份文档里唯一一条**防安全回退**的设计约束，也是本页「先预览后写入」这条安全设计存在的全部理由。
- **「合班」不能当去行话的判据**：26 处里绝大多数是**班名本身**（`A1+A2+A3合班`）⇒ 这是个**永远降不下去的假指标**。
  （与「永久为红的检查 = 死检查」同一条道理。）
- 另有新缺陷：**`batch_ids` 静默覆盖 `batch_id`**（上面选了班、下面勾一个 ⇒ 只排勾的那个，页面一字未提）；
- 三档诚实刻度：精确 / 近似（未扣停课日）/ **「?」**（单双周与周次范围，因为服务端按**学期周次**算，客户端猜会算错）；
- 否决 4 个替代形态并写明理由（免得下一个人再走一遍）。

## 三、综合结论（采用什么）

**骨架取 A**（它已被原型与实测覆盖，且零新增 CSS/JS，风险最低）：
两列字段 + 星期几 chip + 高级项 `▶` 折叠 + 顶部「1 填表 · 2 预览 · 3 生成」进度 + 主操作进首屏 + sticky 动作条（已裁定加）。

**「停用」取 C 的 `?tool=` 服务端 Tab**（+2 行控制器、**不新增菜单**），**并保留 A 的页脚一行次级链接**：
- 为什么不取 A 的新路由 + 新菜单：C 的方案更便宜（+2 vs +12 行）且**服务端分流 ⇒ 表不在 DOM 里**，同样达成「不同屏」；
- 为什么仍要 A 的页脚链接：Tab 之外得有个**可发现的入口**，否则用户找不到它。

**必取 C 的「还没查」诚实块**（哪怕不做两栏，也要有这一条状态行）：
这是三份文档里**唯一防止用户误以为「已经检查过」**的机制。若只能保留一件事，保留它。

**必取 B 的 48 条文案对照表** + A 的逐条对照表，两者合并成一份改稿清单。

**不做**：B 的分步向导（C 已推演并否决；且它会引入「required 隐藏字段让 HTML5 校验静默失败」这一类新坑）。
**不做**：C 的完整两栏实时预览（价值高但改动面大）—— 先做单页 + 诚实状态行，两栏留作后续可选。
