# 周期排课 `/timetable/bulk` —— 方向 B：分步向导（Wizard）

> **状态**：`仅设计` ｜ **主题**：`周期排课 UI 整治（三方向并行，本文 = B）` ｜ **日期**：2026-10-04
> **作者**：设计子代理 B（分步向导方向）｜ **基线文档**：[`docs/design/timetable-bulk-baseline.md`](timetable-bulk-baseline.md)
> **本文未改一行产品代码**：`custom_addons/` 未动、未 commit、未新增路由实现。全部读数与截图为本机 Playwright 实测。
> **一句话**：把 41 个控件的一次性长表单，拆成**四个各自一屏的步骤**；步骤 4 就是**已经存在的预览页**（既有「先预览后写入」的安全设计原样保留）；「批量停用」整体搬出本页成为独立工具。

## 0. 结论速览（TL;DR）

| 问题 | 本方向的答案 |
|---|---|
| 四步怎么分 | ① 排什么（课程/科目/教师/教室）② 排给谁（班级）③ 什么时候（时间/星期/周次/日期）④ 核对并生成 |
| 预览放哪 | **第 4 步 = 现有 `/timetable/bulk/preview` 页**；不在前面随便看（字段没填完看预览只会看到一片报错） |
| 步骤能跳吗 | **已走过的步骤可跳**（点步骤条 / 摘要行「修改」）；**没走过的步骤不可跳**，置灰并写「还差什么」 |
| 改上游要不要让下游失效 | **不清空任何已填值**。上游改动只让第 4 步的预检结果标记为「需重新核对」，并在下次进入第 4 步时自动重算 |
| 批量停用放哪 | **独立门户页 `/timetable/batch/deactivate`（列表）→ 现有确认页不动**；菜单并入「停课管理」组 |
| 要不要动控制器 | **要，但很小**：约 **+25~30 行**（回显 params/step + 一个列表路由 + 修掉「报错清空表单」缺陷）。**零处改字段名、零处改提交目标** |
| 关键前提（实测） | `POST /timetable/bulk` **今天就返回 200**（`odoo/http.py:791`：methods 未指定 ⇒ 全部方法允许）⇒ 步骤间导航**不需要新增路由**，一个表单 + `formaction` 即可 |
| 换来什么 | 每一屏的主操作都在首屏；小灰字从 **79 → 单屏 ≤ 6**；内部代号（全角括号）**17 → 0**；两个工具分开；报错不再清空表单 |
| 牺牲什么 | 跨步改字段多一跳；老手不能一屏扫完；「一屏看全」的爽感换成「不会漏填」的确定性 |

### 1.3 我新发现的三件事（会改变实施排期）

**(a) 任何服务端校验失败 ⇒ 整张表单被清空。**（严重，且与三个方向都有关）

复现：填齐课程/班级/科目/教师/节次/起止日期 + 周次 `1,3-5`，**故意不勾星期几** → POST `/timetable/bulk/preview`。

读数（浏览器里量回来）：

| 字段 | 出错后 |
|---|---|
| `course_id / batch_id / subject_id / faculty_id / timing_id` | 全部回到「— 请选择 —」 |
| `start_date / end_date / week_ranges` | `""`（空） |
| 错误提示 | 「请至少勾选一个星期几。」（`#wrap .alert-danger`） |

原因：`controllers/main.py:694-701` 的错误回退只传 `error`（+`selected_batch_ids`），而 `views/templates.xml` 的表单控件**没有任何 `t-att-value`**。⇒ 用户白填 12+ 个字段。

**对 B 方向的意义**：向导如果只做视觉分步、不做回填，会把「白填 12 个字段」放大成「白填 3 步」。所以本文把「回填 + 出错回到出错那一步」列为**必做项**，不是优化项。这也是 B 方向对 A/C 方向的公共贡献。

**(b) 页头提示条在说一个已经删掉的功能。**

`templates.xml:21-26` 原文：「……本工具只负责批量生成与**整周复制**。」而 `/timetable/copy` 已于 **2026-09-15 按用户裁定删除**（`docs/code-map.md:125`、`docs/audit/deprecated-inventory.md`）。这条提示同时出现在**排课页与预览页**两处。

**(c) 79 处小灰字里，55 处属于另一个工具。**

| 容器 | 小灰字数 | 高度 |
|---|---|---|
| 排课表单卡（`form.card`） | **22** | 1000 px（top 274） |
| 停用卡（第二张卡） | **55** | **763 px**（top 1298） |
| 页头提示条 | 1 | 39 px |
| 其它（面包屑/页脚） | 1 | — |
| 合计 | **79** | 2290 px |

⇒ **「批量停用」搬走 = 一次性减掉 70% 的小灰字与 33% 的页高**。这是一个不需要任何设计技巧的净收益，先做它。

## 2. 调研依据（铁律 0）

### 2.1 外部一手依据：GOV.UK Design System（`web_fetch` 直取，非二手）

`web_search` 工具本轮**不可用**（`HTTP 400 — You have insufficient credits`，与 `docs/research/ui-usability-discoverability.md` §0 记录的是同一个故障）。改用 `web_fetch` 直取官方 pattern 页，全部 200：

| # | 依据（一手 URL） | 原文要点（逐字） | 用在哪 |
|---|---|---|---|
| R1 | [Check answers](https://design-system.service.gov.uk/patterns/check-answers/) | 「Show a single check answers page **immediately before the confirmation screen**」；「provide a 'Change' link next to each section」；「make sure information they've already entered is **pre-populated**」；「only show sections that are **relevant** to users」；「(optional)」要标出来；没答的可选项显示「Not provided」 | 第 4 步的形态；摘要行「修改」；**错误回填**（§1.3a） |
| R2 | [Question pages](https://design-system.service.gov.uk/patterns/question-pages/) | 「Asking just **one question per question page** helps users understand what you're asking them to do」；「Always include a **Back** link at the top」；「do not break the browser back button」；「you can also include a **progress indicator**」（有条件）；「**Do not use the same page heading across multiple pages**」 | 每步一个主题；每步都有「上一步」；步骤条；四步标题必须各不相同 |
| R3 | [Complete multiple tasks](https://design-system.service.gov.uk/patterns/complete-multiple-tasks/) | 任务列表用于「longer transactions involving multiple tasks that users may need to complete over a number of sessions」；状态标签「Start with the smallest number of different statuses」 | 步骤条只用两态（已答/当前）；不引入「进行中/未开始」第三态 |

> R2 对「进度指示」是有条件的（「**If research shows it's helpful**」）。我仍推荐步骤条，理由有二：① 它同时承担**导航**（回跳已答步骤）职责，不只是装饰；② 本页确实有 4 步、且移动端要滚 3 屏以上，用户需要知道「还剩多少」。**这是判断，不是引用** —— 若日后教务反馈步骤条多余，砍掉它的成本是 1 个 partial。

**默认折叠 / 展开的规矩**（一句话：**折叠只放「已经会的可以不看」的东西，绝不折叠「不知道就会填错」的东西**）

| 内容 | 处置 | 理由 |
|---|---|---|
| 「＋ 找不到课程/科目？在这里新建」 | **折叠**（默认收起） | 90% 的排课用已有课程；它是例外路径。也是把 2 个文本框从第 1 步移出去的手段 |
| 「时间怎么错开？」（原 119-124 那段） | **折叠** + 右侧实时「排课顺序」预览 | 把「读一段话才能懂」换成「看一眼顺序就懂」 |
| 「留空 = 自动」等默认值语义 | **不折叠**，写成 placeholder（如 `留空：自动`） | 这是**会填错**的信息 |
| 周次语法（原 225-228） | **折叠成一个 `?` 按钮**，label 与 placeholder 已给例子 | 例子（`1,3-5`）比语法说明有效 |
| 自定义时间「按 15 分钟对齐」 | **不折叠**，但只在选中「自定义时间」时出现 | 条件显示 = 天然降噪 |
| 停课日名单 | **展开**（它是「你会少生成几节」的原因，必须可见） | 安全相关，不给折叠 |
| 冲突图例（四色点） | **展开** | 同上 |
| 逐日期明细 / 周矩阵 | 保持现有 **`<details>` 折叠** | 现有做法是对的，不动 |

### 3.3 控件盘点：41 个控件 → 每步几个（保证「功能一个都不能少」）

> **诚实的说明**：第 2 步的 17 个班级复选框**数量降不下来**（库里就是 17 个班）。能做的是三件事，让「17 个」不再可怕：
> 1. **分两组**：「年级班」（神学一/二/三年级、人文一~四年级、预备科 = 8 个）、「合班（多个年级一起上课）」（9 个）；
> 2. **去掉括号里的内部代号**（`（A123）`），把代号移到 `title` 与 `aria-label`；
> 3. **加「全选本组」**与右上角「已选 N」计数。
>
> 另外要提前说清楚（**给队长的风险提示**）：17 个班级里 **9 个的班名本身带代号**（`A123+B1合班`、`B1-B4全体`、`A1+A2+A3合班` …）。去掉 `（代号）` 后，**基线那台「全角括号」量具会读到 0**，但人眼仍会在班名里看到 `A123`。要做到「人眼也 0 处」，得改 `op.batch.name` 的**数据**（如 `A1+A2+A3合班` → `神学一~三年级合班`）—— 那是数据变更、要教务确认，**不在本次呈现层设计的范围**。请队长裁定是否单开一条。

### 3.4 「批量停用」放哪：**独立页**（推荐）

**推荐形态**：新增只读列表页 `GET /timetable/batch/deactivate`，内容 = 现在搬走的 17 行表（文案改口，见 §5.3）→ 点某行的「停课」→ **进现有确认页 `/timetable/batch/<id>/deactivate`（一行不改）**。

理由，按重要性：

1. **基线 §三 第 5 条要求「不再同屏混排，要一眼看出是两个工具」**——独立页是唯一无争议的满足方式（`<details>` 折叠仍是同页，见下面的降级档风险）。
2. **收益立刻可量**：55/79 的小灰字、763/2290 的页高、14 个「停用…」按钮一次性从排课路径消失（§1.3c）。
3. **确认页已经很好**（截图核实：影响面三卡「23 节 / 0 人 / 停用后」+ 按科目分布 + 二次确认勾选 + 审计说明都是人话），**零改动是最大的省钱**。
4. **语义正确**：排课是「写入新课节」，停用是「撤回旧课节」，方向相反；放同一页会让人以为它们属于同一次操作。菜单上与现有的「停课管理」（`views/menu.xml:17-22`）同组也比挂在排课入口下更自然。

**降级档（若队长坚持零新增路由）**：把 17 行表收进本页尾部一个 **`<details>` 区块**，标题写死「另一个工具：批量停课（只停旧课，不生成新课）」。代价：仍是同页同屏（展开后），**基线第 5 条有被判不合格的风险**；收益是控制器 0 行改动。我**不推荐**，但把它写在这里，因为它是一行代码级别的备选。

**明确不改**：`/timetable/batch/<id>/deactivate`、`/confirm`、`_batch_rows()`、`op.batch._deactivate_composition()`、`deactivate_batch_sessions()` —— 二次确认的服务端判据一个字都不动。

## 4. 交互流程

### 4.1 主路径（用户从进页面到写出课表）

```
进 /timetable/bulk
   │
   ├─ 顶部：步骤条 ①─②─③─④（①=当前，其余=未走）
   ├─ 第 1 步：排什么  ──[下一步]──▶ 校验本步 4 项必填
   │                              ├ 有错 → 就地红字（字段下方），停在原步
   │                              └ 通过 → POST ?step=2（同表单 formaction）
   ├─ 第 2 步：排给谁  ──[下一步]──▶ 校验：至少 1 个班
   │                              └ 通过 → POST ?step=3
   ├─ 第 3 步：什么时候 ─[下一步：核对]─▶ 校验：≥1 个星期几、日期顺序、跨度≤366 天、周次语法
   │                              └ 通过 → POST /timetable/bulk/preview（目标不变！）
   ├─ 第 4 步：核对并生成（= 现有预览页）
   │      ├ 摘要四行（每行 [修改] → 回对应步骤，已填值保留）
   │      ├ 预检结果：0 冲突 → 绿条；有冲突 → 红卡 + 明细（整批拒绝）
   │      └ [确认生成 N 节] ──▶ POST /timetable/bulk/create（不变）
   └─ 结果态：/timetable/bulk?created=N&failed=M
          ├ 成功横幅（现有 42-55 行保留）+ 新增按钮「再排一门（沿用本班与时间）」
          └ 失败横幅（现有 56-61 行保留）+ 「看冲突明细」
```

**每步看到什么 / 反馈在哪**

| 步 | 页面标题（四步各不相同，R2 要求） | 主操作 | 反馈位置 |
|---|---|---|---|
| 1 | 排什么课 | `下一步：排给谁 →` | 字段下方一行红字 + 步骤条①标红 |
| 2 | 排给哪些班 | `下一步：定时间 →` | 班级组下方 + 右侧顺序预览高亮该班 |
| 3 | 什么时候上 | `下一步：核对 →` | 字段下方 + 顶部「共 3 周 · 预计 6 节」实时回显 |
| 4 | 核对并生成 | `✓ 确认生成 6 节课` | 顶部绿条/红卡 + 冲突明细表 |

**进度感**（回答「中途没有进度感」）：三处同时给：
1. 顶部步骤条（①②③④，已答打勾、当前高亮）；
2. 每步页首一行 `第 2 步，共 4 步`（给屏幕阅读器与滚动后迷失的用户）；
3. **第 3 步的实时节数预告**「共 3 周 · 预计 6 节」——纯日期算术，不查库、不预检（冲突留给第 4 步），但它能立刻回答「我这样填会排出来多少」。

### 4.2 步骤条规范（复用 `.ux-steps` 视觉）

- 四段：`排什么 → 排给谁 → 什么时候 → 核对`（4~6 个汉字/段，375 宽下换行也不断词）。
- **只用两态**：`已答`（`.ux-step--done`，打勾）与 `当前`（`.ux-step--current`）。**不引入「进行中/未开始/跳过」第三态**（依据 R3「状态从最少开始」）。
- 已答的段落是**链接**（可回跳）；未答的段落是 `<span aria-disabled="true">` + 一个 `title`/可见小字说明「还差什么」（如「先选课程」）。
- 不让步骤条承担报错样式：错误用**步骤条下方的一条 `.alert-danger`**（就地），不要给圆点染红（颜色语义与「冲突红」打架）。

### 4.3 步骤能不能跳？（想清楚了）

| 情形 | 规则 | 为什么 |
|---|---|---|
| 已走过的步骤 | **可跳**（点步骤条 / 第 4 步摘要行的 `[修改]`） | R1：「provide a 'Change' link next to each section」 |
| 没走过的步骤 | **不可跳**，置灰 + 写明所缺 | 第 2 步需要第 1 步的教师/教室才能预检；第 3 步需要班级集合才能算「每班顺延」；第 4 步需要前 3 步才能算冲突。允许乱跳只会把错误推迟到第 4 步爆发 |
| 浏览器后退键 | **必须自然工作**（R2：「do not break the browser back button」） | 用 POST 到 `?step=N` 的普通导航（非 JS 状态机）天然满足；返回时页面状态与上次一致（**靠回填**，这正是 §1.3a 的修复项） |
| 刷新页面 | 停留原步、保留已填值 | `?step=3` + 已答字段随表单提交或留在 URL 上 |

> 这是一个**明确的取舍**：放弃「任意顺序填写」的灵活性，换「每一步都保证前置条件已满足」。GOV.UK 的 task list（R3）允许任意顺序，但那是给「可以分几次会话完成的长事务」用的；本页是一次坐完的 4 步，线性更合适。

### 4.4 改了上游，下游怎么办（失效规则）

**规则一句话：不清空任何用户填过的值；只让「依赖上游结果的东西」标记为过期并重算。**

| 改哪里 | 影响谁 | 处置 |
|---|---|---|
| 第 1 步 换课程/科目/教师/教室 | 第 4 步的冲突预检结论 | ① 第 3 步的日期/星期/周次 **原样保留**（与第 1 步无依赖）；② 第 4 步摘要里这行标「已更新」；③ 进第 4 步时服务端重新预检（`/preview` 每次都重算，天然满足） |
| 第 2 步 改班级集合 | 第 2 步自己的「排课顺序/首班」；第 4 步节数 | ① **不重建**已填的「每班顺延」（留空就是动态语义，本来跟班级数走）；② 顺序预览重排，新加入的班排在末尾；③ 已选但被取消的班从顺序里移除（不保留幽灵行） |
| 第 2 步 从「多个班」切到「一个班」 | `stagger_minutes` | **不删值**，把输入框**置灰并写明**「只在多个班时使用」；切回多班时值还在 |
| 第 3 步 改开始日期 | 「第 1 周」锚点（`_term_anchor_info(start)`）→ 周次范围的含义 | ① 不删周次输入；② 就近回显「第 1 周从 2026-06-23 算起」；③ 第 4 步摘要必须显式回显「周次锚点」（现有预览页 602-605 行已有这一行，**保留**） |
| 第 3 步 改「上课时间」 | 第 2 步的顺序预览时刻 | 顺序预览的时刻重算（它是派生显示，不是用户输入） |

**唯一的真失效**：第 4 步的预检结果。处置 = 第 4 步顶部出现一行「设置已修改，下面是重新预检的结果」，用户不需要任何操作（自动重算）。**不做「修改后清空下游」这种杀伤性行为** —— 它就是 §1.3a 那个缺陷的温和版本。

### 4.5 预览放最后一步还是随时可看？

**结论：只在第 4 步，但「随时可达」——即只要第 1–3 步完整，第 3 步的「下一步：核对」就是唯一的正式入口；不允许在字段没填完时预览。**

理由：
- 预览页的语义是「**将要写入的东西**」，字段没填完时打开它只会得到一页红字（`请选择课程或填写新课程名。`），把「安全设计」变成「报错墙」。R1 也明确：check answers 页应「**immediately before the confirmation screen**」。
- 保留的旁路：第 4 步永久可达（已填完时）；用户想反复看，用浏览器的后退/前进即可。

### 4.6 校验与反馈矩阵

| 校验 | 何时（即时 / 下一步 / 服务端） | 反馈文案由谁定 |
|---|---|---|
| 课程/科目/教师为空 | 点「下一步」时（第 1 步） | 前端文案，**与 `main.py:358-365` 的既有判词逐字一致**（不造第二套话术） |
| 班级未选 | 第 2 步「下一步」 | `main.py:360-361` |
| 星期几一个没勾 | 第 3 步「下一步」 | `main.py:372-373`（**这条今天会让用户白填 12 个字段，见 §1.3a**） |
| 日期为空 / 结束早于开始 / 跨度 > 366 天 | 第 3 步「下一步」+ 输入时就地 | `main.py:368-375` |
| 周次语法非法 | 第 3 步，输入框失焦即提示 | `parse_week_ranges` 的既有容错（非法片段被忽略）；前端只做提示，**不拦**，避免与后端判据不一致 |
| 时间冲突（四查） | **只能在第 4 步（服务端）** | `_slot_conflict_dims` / `_multi_block_message` 的既有判词 |
| 二次确认（停用） | 服务端判据（`main.py:862-865`） | **不动** |

**红线**：前端的每步校验必须**逐字复用**服务端的判词，且前端只负责「少跑一趟」，**不得成为唯一防线**。服务端把全部判据再走一遍（现有代码已经如此，不动）。

### 4.7 键盘与无障碍（最低要求）

- 每步的 `<fieldset>` + `<legend>`；`legend` 与页面标题一致（R2：「set the contents of a legend or label as the page heading」，避免屏幕阅读器读两遍）。
- 步骤条是 `<ol>` + 每项一个链接或 `aria-disabled` span；当前步 `aria-current="step"`。
- 切步后**焦点移到新步骤的标题**（`tabindex="-1"` + `focus()`）——否则屏幕阅读器用户不知道页面变了。
- 必填用 `required` + `aria-required`，并在页脚一行说明「带 * 为必填」（**不要**只靠一个 `*`）。
- 进度条/步骤条的圆点不得只靠颜色区分（已答打勾 + 当前加粗，满足色盲可用）。
- 现有页面**没有** `<h1>`（只有 `<h4>`），本次改造顺手把每步标题提到 `<h1>` —— 这是一个**既有的无障碍缺陷**，顺手修。

## 6. 取舍

### 6.1 牺牲了什么

| 牺牲 | 谁会难受 | 缓解 |
|---|---|---|
| **一屏看全**：老手不能同时看到「课程+班级+时间」再一次性改 3 个字段 | 一学期排几十次、闭着眼都会填的教务 | ① 第 4 步摘要每行 `[修改]` 一步直达；② 提供「再排一门（沿用本班与时间）」把高频重复路径从 12 步压到 2 步 |
| **多 2~3 次点击**（每步一次「下一步」） | 所有人 | 换来回填与逐步校验；净账在「不再白填 12 个字段」上 |
| **「预览」不再是一键** | 习惯先点预览看看的人 | 第 4 步随时可达（前 3 步完整即可）；不需要变化任何提交链路 |
| **没法任意跳步** | 只想改「时间」的老手 | 已答步骤可跳；第 4 步摘要直达 |
| **改动比纯 CSS 大**：要动控制器 ~30 行、模板大重排 | 维护者 | 换来「报错不清空表单」「两工具分开」「可复测的读数」；且**零处改字段名/提交目标**，风险面可控 |
| **依赖样式下沉或自带 CSS** | — | §7.3 两个方案，都不引入新框架 |
| 步骤条占 ~40px 纵向空间 | 375 宽用户 | 手机上四段折行显示，仍比滚 7168px 好 |

### 6.2 换来了什么

- **主操作进首屏**：按现有 DOM 的纵向分布算（表单卡 274 起、多班块 411-717、时间块 854-1110、日期 1134-1172）——第 1 步主按钮约 **475px**、第 2 步约 **700px**、第 3 步约 **760px**，**三步都在 1000px 首屏内**（基线要求 ≤1000px 或「每步主操作都在首屏」）。
- **小灰字 79 → 单屏 ≤ 6**（预测；见 §7.5）。
- **两个工具一眼分开**：排课页不再出现「停用」。
- **报错不再清空表单**（修掉 §1.3a 的实测缺陷）。
- **移动端可用**：7168px 的滚动拆成 4 段。
- **内部代号与人话**：括号代号 0、行话 0、陈旧文案 0。

### 6.3 什么时候这个方向是错的（反判据，写给队长）

- 如果教务实际上**一个学期只排 2~3 次课**、且每次都是「一个班、一个时间、一个科目」的简单场景 —— 那么 4 步向导的**学习成本与点击成本**可能不如「修好现有单页」（少灰字、去代号、搬走停用表）。**这个数据本文没有**（无访问日志，见 §2.3）。
- 如果教务大量使用「跳着填」（先填时间再回来选课），线性向导会持续硌人。
- **判据建议**：先做**无争议的那一半**（搬走批量停用 + 去代号 + 改文案 + 修回填），复测一遍；如果那时页面已经「不乱了」，向导可以降级为可选项。**但注意**：搬走停用表 + 去代号预计只能把「乱」解决约 70%，**主操作仍在 1220px、仍要一次面对 22 处灰字与 17 个复选框** —— 剩下的 30% 正是向导要解决的。

## 8. 不做 / 排除的路径（记一笔，省得下一个人重走）

| 被排除的方案 | 为什么排除 |
|---|---|
| **纯前端 4 个 `<fieldset>` + `display:none` 切步（零控制器改动）** | ① 41 个控件与全部灰字仍在 DOM 里 ⇒ 基线那台 `querySelectorAll` 量具读到的是**未下降的数字**，验收会打脸；② 隐藏的 `required` 字段会让 HTML5 校验静默失败（"An invalid form control is not focusable"）；③ 报错清空表单的缺陷**不会**被修掉。→ 只把它当降级档 |
| **用 JS 在切步时把非当前步的 `.form-text` 从 DOM 里删掉** | 是「骗量具」，不是「减噪」；且回跳要重建节点、禁 JS 直接崩。**明确不做** |
| **在字段没填完时就能点「预览」** | 会得到一页红字（`请选择课程…`），把安全设计变成报错墙；R1 要求 check answers 紧邻确认页 |
| **把「批量停用」做成第 5 步** | 它是**相反方向的写操作**（撤回旧课节），塞进「排新课节」的向导里会让人以为属于同一次操作；且它的确认页本身就是个独立的安全设计 |
| **给 17 个班级加搜索框/虚拟滚动** | 17 个不是 170 个，分组 + 全选足够；搜索框本身又是一个控件与一处灰字 |
| **把班名里的代号也一起改掉（`A123+B1合班` → 人话）** | 那是**数据变更**（`op.batch.name`），影响后台列表、报表、历史课节与既有深链；需教务确认，**不在呈现层设计范围**（§3.3 风险提示已上报队长） |
| **步骤条做成可点击的任意跳转** | 违反 §4.3 的前置依赖；已答步骤可跳、未答不可跳是刻意的 |
