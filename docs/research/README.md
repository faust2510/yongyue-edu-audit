# 调研档案（docs/research/）

> **铁律 0 的落盘处**：任何功能在进入设计前，先在这里留下一份带一手来源的调研。
> 见 `CLAUDE.md` 铁律 0 与 `docs/dev-workflow.md` 六步闸门第 2 步。

## 收录规范

1. **文件命名**：`<主题>.md`，主题用能检索的中文或英文短语（例：`odoo19-debranding-i18n.md`）。
2. **每条结论必须带一手来源 URL**：官方源码（给 commit/分支 + 文件路径 + 行号）、官方文档、开源仓库源码、产品帮助中心。
3. **无法核实的必须标「未验证」**，并且不得当作结论使用；不确定的地方写清楚"未验证"的原因（站点 JS 渲染 / Cloudflare 403 / 需登录等）。
4. **行号会漂移**：引用上游源码行号时，注明取证的 commit 或分支；本地镜像版本不同会导致行号偏移，**实施时以本机实测为准**。
5. **区分「可复用」与「必须自研」**：可复用的给模块名/仓库/license/版本支持；必须自研的给推荐实现手段。
6. **末尾写"未验证 / 待确认"清单**，让下一个人知道边界在哪。
