## 一句话：它是干什么的

给学校在 Telegram 上配一个**行政班务助手**：帮您**定时发通知**、**替您点名催人**、**一条命令广播到群里**、
**别人 @校长没回就私聊提醒**，还有**现成文案模板**可套。

它**不是**学生那个匿名意见箱（那是另一个机器人，两套东西完全分开，见本文最后一节）。

## 不想记指令？点按钮就行（2026-10-13 新增）

2026-10-13 有老师反馈「让不写代码的人记斜杠命令，学习成本有点高」。现在**多了一排按钮**：
私聊机器人发一句 **`/menu`**（或者 `/start`、`/help`），输入框下面就会常驻一排按钮，
一直挂在那儿，不用记任何指令。**原来的斜杠命令一条都没删**，老用法照旧。

**行政 / 管理员看到 6 个按钮**（3 行 × 2 个）：

```
📢 发通知到群     ✉️ 私发给某人
📄 文案模板       👤 我的身份
📚 使用说明       🔕 停止私发
```

**非行政的老师看到 4 个**（发通知、私发那两个管理按钮不出现 —— 点了也只会回「你没有这个权限」）：

```
📄 文案模板       👤 我的身份
📚 使用说明       🔕 停止私发
```

点下去之后是**一步步点**，每一步都有回话，不会「点了没反应」：

| 点哪个 | 会发生什么 |
|---|---|
| 📢 发通知到群 | 列出后台登记过的群（有短名的排前面）→ 点一个群 → 它说「把要发的内容发给我」→ 你发一条文字 → **先给你看预览**，点「✅ 确认发送」才真的发出去 |
| ✉️ 私发给某人 | 列出人员映射里的教职工 → 点一个人 → 发内容 → 预览 → 确认（成功失败都会留一行私发记录） |
| 📄 文案模板 | 列出现成模板 → 点一条，渲染好的文案**发给你自己**看（这一步不会发到群里） |
| 👤 我的身份 | 相当于 `/whoami` |
| 📚 使用说明 | 相当于 `/help`（按你的身份给不同版本） |
| 🔕 停止私发 | 相当于 `/stop`：不想再收一对一私发就点它，重新发 `/start` 恢复 |

> **两条安全底线**：① **发出前一定有预览**，点「✅ 确认发送」才出网；② 发一半去发了别的指令，
> 草稿会被自动丢掉（不会把没确认过的话发出去）。越权点管理按钮会**留痕**（后台私发记录里 state=denied）。

> ⚠ 按钮看不见的两种情况：① 手动把键盘收起来了 → 发一句 `/menu` 叫回来；
> ② 群里默认没有这排按钮（群里的按钮由广播里那张图/那条消息自带）。

改菜单：`bash scripts/set_bot_commands.sh`（token 见「技术备注」）。菜单是**所有人共用**的，
学生也看得到老师那几条，所以新加命令时请在描述里写清"谁用"。

### 🖥 打开面板（Mini App，2026-10-13 新增）

面板有**三处入口**（2026-10-14 统一过，都指向同一个面板、同一套验签）：

1. **底部键盘最后一行「🖥 打开面板」**：点一下，机器人回你一条消息，**再点那条消息里那颗「🖥 打开面板」** 就开面板。
   为什么要点两次：键盘上的按钮是 Telegram 画的，它「直接开网页」的形态在**电脑版**会被当普通链接打开、
   拿不到身份数据、只显示 `no initData`（2026-10-14 用户实测；同一个按钮手机版正常）。改成纯文字按钮后各端都正常，
   代价就是多点一次。
2. **消息里那颗「🖥 打开面板」**（内联按钮）：发 `/menu` 就会给你一条，点它**一步**开面板 —— 这是官方列的启动方式，各端都认。
3. **电脑版输入框旁边那颗 Telegram 自带按钮**：已给行政/教务设成「打开面板」，点一下直接开。
   （它原来是「命令列表」按钮；想恢复成命令列表跟我说一声，或者在系统参数里把 `edu_tg_assist.menu_button` 改成 0。）

面板跟按钮是同一套能力、同一个账号，只是换成「一屏看完 + 表单直接填」的样子：

| 面板里能干什么 | 谁可以 |
|---|---|
| 看自己的身份（姓名 / 角色）与使用说明 | 已登记的所有人 |
| **📢 发通知到群**：选群 → 填正文 → 发（同样走 send_log 留痕） | 行政 |
| **✉️ 私发给某人**：选人 → 填正文 → 发（同样留私发审计） | 行政 |
| **📁 材料归档**：翻材料、看摘要、直接**转发**给某个人或某个群（有文件就走 file_id，不重传） | 教师 / 宿舍长 / 行政 |
| **⏰ 定时群发**：选群 → 写正文 → 选星期几点，以后每周自动发；列表里可「立即发一次 / 停用 / 删除」 | 行政 |
| 人员名单（谁登记了、什么角色） | 行政 |

三条要知道的：

1. **面板就是机器人本身**：它验的是 Telegram 当场给的签名（initData），网址转发给别人也没用 —— 别人点开只看到「身份校验没通过」；
2. **学生看不到材料**：材料归档这一页只对**教师 / 宿舍长 / 行政**开放，别的人点了会被拒（并留一条越权审计）；
3. 面板里**没有**「改群短名」——那个还是老办法：在群里发 `/alias 学习群`（见下一节）。

面板地址（给技术的人看）：`/edu_tg_assist/app`（页面）与 `/edu_tg_assist/app/api`（接口）。
两个地址都只用本模块自己的 `edu_tg_assist.token` 验签，**没有**碰意见箱、领码机器人或那三条 webhook。

**打开只看到一条红字怎么办（2026-10-14 更新）**：红字是它在**保护自己** —— 面板只认 Telegram 当场给的签名，
没拿到签名就谁都不许用（包括把链接转发出去的人）。看到红字请照这个顺序试：

1. **电脑版**：发一句 `/menu` → 点回信里那颗 **「🖥 打开面板」** 内联按钮（或者点输入框旁边那颗菜单按钮）；
2. **手机版**：发 `/menu`，或点底部键盘最后那排的「🖥 打开面板」→ 再点回信里那颗按钮；
3. **别**把链接复制到浏览器、也别点别人转发的链接 —— Telegram 不会给它们身份数据，一定打不开；
4. 还不行：把红字下面那行 **「要发给管理员的信息」** 原样截给我。里面有 `hkeys=`（hash 里有哪些键，
   **只列键名、不含签名**）：有 `tgWebAppData` 却读不到 = 我们解析的问题；只有 `tgWebAppPlatform/ThemeParams`
   = 客户端压根没按 Mini App 方式打开。

（2026-10-14 那次红字的读数是 `tg=yes initData=0 hash=713`：SDK 活着、但客户端没给签名 ⇒ 电脑版把键盘上的
web_app 按钮当成普通链接打开了。所以又加了一条**内联按钮**的路，两条路指向同一个页面、同一套验签。）

### ⏰ 定时群发：不用进后台，面板里就能设（2026-10-14 新增）

以前「定时提醒」藏在 Odoo 后台里，还要先建一条模板，所以一直没人用得上（后台里模板 0 条、规则 0 条）。
现在在面板里三步就能设好：

1. 点 **⏰ 定时群发** → 点 **＋ 新建定时群发**；
2. 选一个群；
3. 写正文，选 **星期几** 和 **几点几分**，点「✅ 建好，以后每周自动发」。

建好以后回到列表，点这条进去还能：**🚀 立即发一次**（当场看效果，满意就等着它每周自己发）、
**⏸ 先停掉**（停用后不会自动发，随时能再启用）、**🗑 删掉这条**（连它自己的定时任务一起删）。

两条要知道的：

1. **只有行政能设定时群发**；非行政点进去只会看到「你没有这个权限。」，并被记一条越权审计；
2. 时间是**北京时间**，逻辑是「每逢星期几的几点几分」，不是「几月几号发一次」。

- **用码绑好的老师，不会触发那条「新登记…请去后台标角色」的提醒**（2026-10-13 修）：

   保存/发布 —— 就在那一刻发到上面勾好的群。填了「定时发布时间」的公告也一样，到点自动发。
3. **发出去长这样**：`【公告】标题` + 换行 + 正文（最长 3500 字）；每发一条都在
   **「班务机器人 → 发送记录」** 里留痕（`kind=notice`），成功、失败都能看。

两条须知：**没勾「接收网站公告」的群一条都不会收到**（所以不会误发到不该发的群）；
公告里的**附件不会**跟着发到 Telegram，只发文字（附件仍留在网站的公告里）。

### 五条定时任务（两条默认关、三条默认开）

1. **@提醒超时扫描**（默认**关**）—— 每 5 分钟看一次"谁 @了校长、15 分钟没回"，没回的私聊提醒。
   要用 F5 就把它**打开**。
2. **定时提醒规则自愈**（默认**关**）—— 每天一次，修"规则还在、它的定时任务丢了"这种漂移。
   **它不发任何消息**，开着也不打扰人。
3. **发送记录清理**（默认**开**）—— 每天 03:30（UTC）把超过保留天数的发送记录删掉，
   保留天数 = 系统参数 `edu_tg_assist.send_log_keep_days`（默认 90；**配 0 = 一条都不清**）。
   它**不发任何消息**、不影响任何发送功能，只是别让"发送记录"无限长下去。
4. **材料分类归档**（默认**开**）—— 每分钟看一次"有没有老师刚转发的材料还没分类"，有就抽信息、回执；
   没配大模型就只用**关键词规则**，照样能用。它只处理老师私聊发来的材料。
5. **材料归档清理**（默认**开**）—— 每天 03:40（UTC）删掉超过保留天数的归档材料，
   保留天数 = 系统参数 `edu_tg_assist.material_keep_days`（默认 365；**配 0 = 一条都不清**）。

## 它绝对不碰什么（重要）

学生那个**匿名意见箱**是另一套程序。它成立的前提是「**服务器不保存学生的明文 chat_id**」。
所以本机器人立了十二条硬边界，任何一条都不许破：

| # | 边界 |
|---|---|
| B1 | 绝不读写匿名意见箱的任何数据表 |
| B2 | 绝不读写它的发送队列与它的系统参数 |
| B3 | 绝不占用它的接收网址 `/telegram/webhook`（本模块用 `/telegram/assist/webhook`） |
| B4 | 绝不依赖那个模块（可以单独装、单独卸） |
| B5 | 本机器人的 chat_id 与意见箱的指纹**永不合并、永不对照** |
| B6 | token **绝不写进日志** |
| B7 | 前门模块 edu_tg_gate **只做分发**，自己**不存任何数据**（无表、无模型） |
| B8 | 三条接收网址**并存**且各自上锁；学生那条旧网址保留着，随时能一键回滚 |
| B9 | 大模型与 Notion **默认零出网**：参数没配齐，一个字节都不往外发 |
| B10 | 真要出网前先**脱敏**（手机号、身份证、银行卡、邀请码换成占位符） |
| B11 | 材料原文只存本库；送 Notion 默认只送摘要与关键信息，**不送原文** |
| B12 | 归档只对**老师**的私聊生效；学生流一个字不变 |

这些写在 `docs/plans/tg-assist-bot-design.md` 与模块代码注释里，改代码的人一眼能看到。

## 出问题怎么查（给我看这三处）

0. **后台 → 班务机器人 → 自检**：先点这一页，它会把"哪儿不对"直接列出来（✅/❌）；
   尤其看 webhook 网址与 pending 数 —— 小红书式的"它不理人"九成在这儿。
1. **后台 → 班务机器人 → 发送记录**：每一条消息都在这儿，失败会写原因。
2. **后台 → 班务机器人 → 私发记录**：`/dm` 的每一次，包括"被拒绝"的。
3. 常见三种：

| 现象 | 多半是 |
|---|---|
| 它完全不理人 | token 没填 / 填错；或 Telegram 那边的接收网址没注册；或**刚改了系统参数却没重启过 web 进程**（新参数对活着的进程不可见，会一律 403） |
| 它说"没找到名字含 X 的群/人" | 后台「群与短名」或「人员映射」里还没登记 |
| 收到「新登记：某某… 请到后台标成行政/教师/宿舍长」 | 这是机器人**自动**提醒您：有人第一次私聊了它，而且身份还没绑定。若他手里有您发的绑定码，让他 `/bind` 一次就不用您动手；确实还没绑的老师，才需要您到「人员映射」把角色标好 |
| 群里 @校长 没反应 | BotFather 里的隐私模式没关（它读不到群消息） |

## 技术备注（给接手的人）

- 系统参数：`edu_tg_assist.token`（= 库里 `edu_tg_bind.token` 的**同一串**；2026-10-08 起两个模块共用一个 bot，值只在容器内复制、从未进过日志/文档）、
  `edu_tg_assist.dry_run`（2026-10-08 已置 `0` 真发；`1` 时**只落库不出网**，调试用）、
  `edu_tg_assist.webhook_secret`（assist 自带路由 `/telegram/assist/webhook` 用，密钥对不上直接 403）。
- 打卡（F4 接通 F1）另立两张表 `edu.tg.assist.poll` / `edu.tg.assist.poll.reply`，按钮回调前缀 `p:`，
  与 @提醒待办的 `ck:` **分流**（互不抢、各自唯一约束）；不写 `edu.checkin.record`、不碰意见箱的任何表。
- @提醒（F5）还需 `edu_tg_assist.owner_user_id`（校长/被 @ 的人的 Telegram **数字** id；**不配就永远不建待办，不会乱猜谁是校长**）、
  可选 `edu_tg_assist.owner_username` 与 `edu_tg_assist.mention_timeout_minutes`（默认 15），
  并把定时任务「`edu_tg_assist`: @提醒超时扫描」打开；**且必须先关掉 BotFather 里的隐私模式**，否则「@校长」这类消息根本不会投递给机器人。
- 前门（2026-10-08 新增，**当天已上线**）：模块 `edu_tg_gate`，网址 `/telegram/sctrs/webhook`，
  参数 `edu_tg_gate.webhook_secret`（已在生产容器内生成，长度 32）；判据在 `custom_addons/edu_tg_gate/routing.py`（纯函数，单测 `tests/unit/tg_gate_router_test.py`）。
  **Telegram 的回调现已指向前门**（`allowed_updates=["message","callback_query"]`、`pending_update_count=0`、`last_error=None`），
  前门按判据转给领码（`edu_tg_bind`）或班务助手（`edu_tg_assist`）。一键回滚 = 把回调指回 `/telegram/tgb/webhook`（那条路由与它的密钥原样保留）。
- 模块**只依赖 `base`**，不依赖 `edu_portal` / `edu_telegram` ⇒ 可单独装、单独卸。
- **网站公告 → 群（对接 a，2026-10-14）**：门户 `edu_portal/models/notice.py::_send_channels()` 的 Telegram 分支改为「先按模型名探 `edu.tg.assist.bridge` 在不在」，
  在则调 `push_site_notice()` 发给 `edu.tg.assist.chat.notice_enabled=True` 的群（`kind=notice` 进 `send_log`），探不到才回退旧路
  `op.telegram.chat → edu.telegram.outbox`（生产没有该模型，异常吞掉，不拖垮发布）；**门户不依赖本模块**（无 depends、无 import）。
  公告走**主动调用**而不是 id 水位轮询：`edu.notice.active=False` 是「未发布」载体，草稿转发布的 id 会落在水位之下而永远漏发。
- **网站侧权限组（2026-10-13）**：`security/assist_security.xml` 的 `group_assist_manager`「班务机器人管理员」（**不隐含系统管理员**）+ `security/ir.model.access.csv` 追加 14 行
  （配置类 1,1,1,1；审计类 1,0,0,0 = 能看不能改）；根菜单 630 的可见范围由「仅系统管理员」改为「系统管理员 + 班务机器人管理员」。
  给教务开账号 = 「后台·完整视图」+「经理」+「班务机器人管理员」；单测 `tests/unit/tg_assist_security_test.py`（26 条），设计 §9.15。
- 命令菜单（Telegram "/" 列表）：原本只有一条 BotFather 手工设的 `/zhuce`，2026-10-09 起由 `scripts/set_bot_commands.sh` 发布
  （default + 私聊 9 条、群 3 条；2026-10-10 加 `/stop` 与群内 `/alias`），入库以免再漂。
- **/stop 与 /alias（2026-10-10 加）**：`/stop` 把 `edu.tg.assist.person` 的 `active` 置假并清空 `chat_id`（保留 `tg_user_id`，
  再发 `/start` 自动恢复）—— 因此查人时必须 `active_test=False`；前门判据同样用 `active_test=False`，
  否则停用过的老师会被当成学生去领邀请码。`/alias` 只改**当前群**的短名，撞名直接拒绝、绝不覆盖。
- 后台「自检」= 瞬态模型 `edu.tg.assist.selfcheck`（无表，打开即跑 `api.selfcheck_lines()`）；
  「清理发送记录」= 服务端动作调 `edu.tg.assist.send_log.action_prune_now()`（保留天数参数 `edu_tg_assist.send_log_keep_days`，默认 90，0 = 不清）。
- **本轮明确不做**：webhook 健康告警（Telegram `last_error`/pending 变高时告警）—— 该放在**服务器脚本侧**，
  因为 Odoo 自己挂了才最需要告警，写在 Odoo 里等于自己告自己的警。要做得单独立项。
- **新人通知的时机（2026-10-13 修）**：通知由 `person.notify_new_if_needs_label(rec, was_new)` 在**指令分发结束之后**发，
  只在「这条消息之前他没登记过」且「处理完仍然 `role='other'`」时才发 —— 带绑定码的首次登记（`/start BIND-XXXXXX`）
  是同一请求里先 create（role=other）再 redeem（role=admin），旧写法在 create 那一刻就发，必然给刚绑好的人发假警报。
- 出网方式与 `edu_tg_bind` 一致（`AbstractModel` 里统一出口，绝不把 token 写日志）。
- 设计与硬边界：`docs/plans/tg-assist-bot-design.md`；本地自证与探针：`tests/smoke/tg_assist_mention_probe.py`（已进门禁）。
- **Mini App 面板（2026-10-13）**：两条路由 `/edu_tg_assist/app`（页面，GET）与 `/edu_tg_assist/app/api`（接口，POST）。
  接口只认 `init_data` 签名（`miniapp_auth.py`：`data_check_string` 排序去 hash、`secret = HMAC_SHA256('WebAppData' 作 key, token 作消息)`、
  时效 1 小时、`hmac.compare_digest`；失败只记原因短码，**永不记 init_data 与 token**）。
  权限三层：任何人（whoami/help/groups）、教职工（materials/forward）、行政（notify/dm/staff）；越权写 `denied` 审计。
  入口是底部键盘最后一行的 `web_app` 按钮（`menutext.reply_keyboard`；Telegram 只在私聊接受它）。
  两条路由是**常量式**声明（与三条 webhook 同形）⇒ `check_ui_surface.py` 看不见，因此**不登记** `tests/ui/surface.json`（登记了反而报「已失效」）。
  静态用例 `tests/unit/tg_assist_miniapp_test.py`（54 条，含按官方算法独立实现签名的真样本对拍）。
- **面板的官方 SDK 是自托管的（2026-10-14，§9.20）**：`static/vendor/telegram-web-app.js`（119731 字节），
  页面不再直连 `telegram.org`；`initData` 三层兜底（`tg.initData` → `location.hash` 的 `tgWebAppData` → 明确提示 + 诊断串），
  `waitSdk()` 最多等 2 秒再进业务。
