## 2. ④「改完要不要升级模块（-u）」——最容易白忙的坑

| 你改了什么 | 要不要 `-u` | 为什么 |
|---|---|---|
| **业务数据**：课程名、学分、科目、班级、课节时间/教师、报课单审批 | **不要** | 这些是**库里的记录**，点保存即生效。升级纯属白等 |
| **XML 视图 / QWeb 模板**（门户页面、表单） | **要** `-u <模块>` | 视图存在库里，**只在升级时重载** |
| **Python 逻辑**（控制器/模型） | **要** `-u <模块>` | 进程需重载模块代码 |
| **菜单名 / 译文**（PO、`edu_zh`） | **要** | 数据与译文靠升级重放；PO 覆盖可能还需 `--i18n-overwrite`（否则**已有译文不被覆盖**） |
| 定时任务等 data 记录 | **要** | 同上，靠 data 重放 |

**标准入口（本地）**：`bash scripts/safe_upgrade.sh -u <模块>`

**不要**用 `docker compose exec web odoo -c /etc/odoo/odoo.conf -d edu19 -u <模块>` —— `exec` 会绕过 entrypoint，DB 连接参数不会注入，结果是连不上数据库（本轮实测过：`psycopg2.OperationalError`）。

**四种典型白忙**：
1. **改了视图却没 `-u`** → 页面看着没变，以为改错了；
2. **只改数据却 `-u`** → 等几分钟，什么也没变；
3. **把 `-i` 当 `-u` 用** → 字段建了、**视图没进库**（本轮实测过）；
4. **在升级窗口里跑门禁/冒烟** → 站点正在重启，读数是 ENV 作废（**不要在这种窗口下判断"是不是回归"**）。

# 第二版补充（队长接手块，2026-09-14）

> 依据：`openeducat_erp` 模型定义（`required=True` 逐个读出）+ 本地克隆实测 + 生产库现状。**凡标「实测」的都是真的跑过/读过，不是"应该如此"。**

## 5. ②③ 每个动作：要填什么 → 保存后在哪看到

### 5.1 新建课程（菜单 `263`）
**必填**：名称（可多语言）、**代码**（≤16 字符，全库唯一）、评估方式（默认 normal）。
**保存后在哪看到**：`263` 列表里；**学生端 `/subject/enroll` 的"课程目录"只列「启用」的课程**（停用的不出现）。

### 5.2 新建科目（菜单 `267`）
**必填**：名称（≤128）、**代码**（≤256，全库唯一）、类型（理论/实践/两者/其它，默认理论）、**科目性质（必修/选修，默认必修）**。学分选填。
**最容易漏的一步**：建完科目，还要在**课程（`263`）表单里把它挂到该课程的"科目"页签** —— **没挂到课程的科目，学生在报课页根本看不到**（报课池 = 课程自己的科目表）。

### 5.3 新建班级/批次（菜单 `264`）
**必填**：代码（≤16）、名称（≤32）、**开始日期**、**结束日期**、**所属课程**。
**保存后在哪看到**：学生报课页选中课程后，**班级下拉**里出现它；课表按班级过滤。

### 5.4 新建课节（菜单 `343`，单节）
**六个字段全是必填**：**开始时间、结束时间、课程、教师、班级、科目** —— 少一个存不下去。
⛔ **前置**：必须先有**教师档案**（`op.faculty`）。**生产现状：只有 1 条教师记录「待定」，且没有登录账号** ⇒ 要么先建教师，要么临时指向「待定」（但那样教师端看不到"我的课"）。
**保存后在哪看到**：学生 `/student/timetable` 按**班级**看到；教师端按**教师**看到。

### 5.5 批量排课（推荐，别一节节敲）
- **入口**：`/timetable/bulk` —— **需内部用户身份**（教务/管理员 ✓；学生/家长会被 303 送回首页）。
- **流程**：填参数 → **预览**（`/timetable/bulk/preview`，先看要生成哪些节，**不写库**）→ 确认再**创建**。
- ~~**`/timetable/copy`**（整周复制）~~ —— **已于 2026-09-15 按用户裁定删除**：它与周期排课功能重叠（一个"按规律生成"、一个"搬运已有周"），且生产上**从未被使用过**（216 节课全部由脚本导入）。若日后确实需要"把某周照搬到后面"，恢复步骤：从 git 取出 `edu_schedule/controllers/main.py` 的 B 段与 `views/templates.xml` 的三个模板、`views/menu.xml` 的两条记录。
- **前置与单节相同**：课程 / 班级 / 科目 / 教师都得先存在，否则预览阶段就会报错。

### 5.6 改 / 停用 / 删除
- **改**：打开记录改字段保存即可，**不需要 `-u`**（业务数据不是代码）。
- **停用优先于删除**：课程/科目都有"启用"开关；停用后**不再出现在学生报课池**，但历史资料/成绩的引用不断；**删除会让引用变空**。
- 删之前想一遍：删课节 = 学生课表少一节；**已审批的报课单不要删**（它是档案科目的来源）。

## 6. 学生侧联动（读实现，不是"应该"）

路径：学生在 `/subject/enroll` 勾选提交（与菜单 `281` 同一个模型的**学生入口**）→ 生成 `op.subject.registration`（`state=submitted`）→ 教务在菜单 **`612`** 通过或驳回。

- **通过**（`models/registration.py:133 action_enroll_approve`，实测代码）：自动建/更新该生 `op.student.course`，并把科目**整体覆盖**为报课单里的科目（注释写明口径「**注册单 = 最新意愿**」）；同时**发站内通知**给该生 + 写**审计日志**（"选课审批：通过：档案 X（课程 Y），科目 N 门"）。
- **防呆**：报课单里**一门科目都没有**、而学生档案已有科目时，**拒绝通过并报错**（"通过将清空其档案科目"）—— 不会误清空。
- **驳回**必须填原因（不填会退回并提示）。

⇒ 学生端会变的地方：`/student/subjects`（我的科目）、`/my/study`（逐门展示教师/课节/资料/成绩）、`/student/timetable`（课表）。
⚠ **提醒（会被误读成"科目变多了"）**：通过是**覆盖**不是累加 —— 报课单里勾了几门，档案里就剩几门。

### 8.4 遇到「点进去落回应用面板」怎么报（重要）

有一类问题**不报错、不弹窗、也不 404**，只是**点进去落到了「应用」面板**（或者一直转圈、页面空白）。
这通常意味着「菜单你能看见，但里面的东西你没权限读」—— 也就是**权限没配齐**，属于要修的问题，**不要以为是自己操作错了**。

**报障时请带上这四样**（带上就能一次定位，不用来回问）：
1. **你点的是哪个菜单**（中文名 + 如果能找到的菜单 id，例如「网站 / 活动，373」）；
2. **你看到的结果**：落到应用面板 / 空白 / 报错文案（原样抄）；
3. **时间**（精确到分钟）与你的账号（`backoffice@local` 还是 `jiaowu@local`）；
4. 能截图就截图（画面上有地址栏最好）。
