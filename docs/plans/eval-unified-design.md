### 2.2 6 组硬缺口（引用盘点文档 §10.3）

盘点文档把「6 张表要求、而三套**任何一套**都做不到」的项归纳为 6 组（[§10.3](eval-materials-inventory.md#L621)）：

| # | 缺口（G 编号） | 素材依据 | 现状 | 本文解法 |
|---|---|---|---|---|
| **H1** | **G2 三层分类层级**（类别 → 子项目 → 三级项） | 说明表 1（两级）+ xlsx（三级：一级分类/二级分类/三级） | 三套**全是扁平的**。「生活技能(二级) = 时间管理 3% + 理财习惯 3% + 独立生活 4%」**无法表达** | §5.1 |
| **H2** | **G1 占比语义**（Σ=100% + 自校验） | 说明表 1 全部 14 子项目；xlsx `E27=SUM(E5:E26)` | B/C 的 `weight` 是**倍率**不是占比（B 的 help 原文写「放大倍数」），**无 Σ=100% 校验** | §5.2 |
| **H3** | **G3 客观/主观双轨取平均（且分类别启用）** | 说明表 1「子评分」列；表 2；xlsx `H=(F+G)/2` | 三套都只能「一人一列分数」。C 套 `average = total/份数` 是「N 人评同一维度」的**近似**，不是「客观路/主观路两个固定角色」，也**没有**「某类才有双轨」的分档 | §5.3 |
| **H4** | **G5+G6+G7 扣分制 + 多区段并列 + 分区小计** | `卫生检测表` 整套范式（5 区 × 32 项，每区「项列 + 评分列」，`共计分数` + `总分`） | 三套**一律加分制**（`0 ≤ score ≤ max_score`，汇总只做 sum/加权和）；且都是**单一 table**（行=被评者、列=评分项），做不出「一页 5 段表，每段自己的项数与满分」 | §5.4 |
| **H5** | **G10 整表级「导师评语与建议」** | 说明表 4 `R25`（跨 5 列）；JS 版同 | 三套都**没有任务级/被评者级的总结评语字段**（C 套 `task.notes` 是**任务说明**，不是给被评者的评语） | §5.5 |
| **H6** | **G15 明细行表（时间/地点/内容/金额 + 附件）** | `XS每日实践工作报告单` | 三套**完全没有**：无明细行表、无金额、无附件 | **本期不做**（A5）；边界写法见 §5.6 |

## §3 总体设计：以 C 套为基座扩展

### 3.1 设计总纲

**一句话**：**五层模型一行不改**，只在 `edu.assess.template` / `edu.assess.item` / `edu.assess.task` / `edu.assess.roster` 上加**结构语义字段**，并把汇总算法从「一种」扩到「三种」；录入界面在同一条前端链路上补「冻结 + 整块粘贴」。

    ┌─ 定义层（用户自定义的地方）───────────────────────────────┐
    │ edu.assess.template   模板：满分 / 及格线 / 权重模式 / 刻度 / 等级线开关   │
    │   └ edu.assess.item   评分项 = 一列：层级(parent_id) / 满分 / 权重 /       │
    │                       给分方式 / 扣分制 / 单双轨 …                      │
    ├─ 执行层（一次评估）──────────────────────────────────────┤
    │ edu.assess.task       任务：被评对象 / 打分角色 / 匿名 / 名单范围 / 双轨两路角色 │
    │   └ edu.assess.roster 名单行 = 一个被评者：**+ 整表评语**                │
    ├─ 结果层（服务端算，用户改不动）─────────────────────────────┤
    │ edu.assess.score      单元格：项 × 行 × 打分人 **+ 轨**                 │
    │ 派生显示              项得分 / 组小计 / 区小计 / 总分 / 占比合计 → 不落库    │
    └──────────────────────────────────────────────────┘

**改造面（本设计需要动的东西，全部是"补完"而非"推翻"）**：

| 面 | 现状 | 本期 | 规模 |
|---|---|---|---|
| 数据模型 | 5 个模型、字段齐备但语义不足 | **12 个字段级增项 + 1 处约束变更**（§3.3），**零新模型** | 小 |
| 汇总算法 | 1 种（Σ value×weight 倍率） | 3 种（倍率 / 占比 / 双轨平均）+ 分组小计（派生） | 中 |
| 录入界面 | 矩阵 + 回车下移 + 超分标红（`assess_grid.js` 98 行） | + 冻结表头 + 整块粘贴 + 档位下拉 | 中 |
| xlsx 往返 | 已达标（扁平宽表） | + 三级表头 + 小计行 + 占比校验行（**保住并扩展**） | 中 |
| 权限 | ACL + 行级规则已就位 | 只补"谁能建模板"的显式口径（§7） | 小 |
| 旧两套 | 路由已 303、模型未删 | 按 §8 顺序收口 | 小（有前置依赖） |

### 3.2 「零新模型优先」的论证（逐条）

> **本仓的强口径**：新功能优先「零新模型」—— 先例密集，例如班级管理「零新模型：只给基座加方法」、排课看板「新建（既有模块内只读页，零新模型）」、课程中心入口「零新模块 / 零新模型 / 零新表 / 零新字段」（[scheduling-overhaul-design.md](scheduling-overhaul-design.md#L224)、[study-scheduling-design.md](study-scheduling-design.md#L303)、[code-map.md](../../docs/code-map.md#L429)）。
> 因此本节**先论证能不能不新增**，确实不能的必须写明**为何无先例**。

#### 3.2.1 判定规则（三个问题，按序问）

| 序 | 问题 | 若是 | 若否 |
|---|---|---|---|
| **Q1** | 这个缺口需要一张**新的多值依附表**吗？（一个人/一个模板下能挂**任意多条**、且这些条**不是评分项也不是名单行**） | ⇒ **必须新增模型**，进入 Q1 破例流程 | 进入 Q2 |

### 3.4 必须新增模型的唯一一处：H6（本期不做，写明边界）

**《XS每日实践工作报告单》为什么不能靠加字段解决**：它要的是**明细行表**——序号 1–10 行，每行 = 时间 / 地点 / 工作内容 / 金额，外加 `共计：__元` 与"截图凭证"（[§5 素材 D](eval-materials-inventory.md#L265)、[§10.1 G15](eval-materials-inventory.md#L601)）。按 R1 判定：这是**新的多值依附表**（一个报告单挂任意多条流水行），且这些行**不是评分项**（没有满分/权重/刻度）也**不是名单行**（不是被评者）；金额要汇总、附件要落到某条流水上。

⇒ **它必须新增模型**（约 `edu.assess.line` + 附件绑定），且**仓内无先例**：全仓现有评估三套（12 个模型）没有任何"明细行"结构，`op.assessment`（作业）与它是**不同域**（作业是教学任务，不是费用流水）。因此按仓库铁律 0，"若将来要做"必须先走调研（钉钉/企微的报销流水表单、Odoo 原生 `account.move.line` 式明细行）再设计。

**若将来要进这个引擎，边界会这样扩大**（本设计预先写明，避免下次从零论证）：

| 维度 | 现在的边界 | 报告单进来后的边界 |
|---|---|---|
| 引擎的"一行"是什么 | 一个人（学生/教师） | 一个人 **或** 一张单（单据成为被评/被记对象） |
| 单元格类型 | 数值 / 档位 | 数值 / 档位 / **文本 / 日期 / 金额 / 附件** |
| 条目语义 | 评分项（有满分、权重、刻度） | 评分项 **或** 无满分流水项 |
| 汇总 | 加权、双轨平均 | 再加**金额求和**、**附件必填校验** |
| 表形态 | 矩阵（行×列） | 矩阵 **或 明细子表**（主表 + 行表） |
| 触发的新模型 | — | **至少 2 个**（明细行 + 附件绑定），破例必要 |
| 前端 | 矩阵 + 冻结 + 粘贴 | 再加**动态增行 + 附件上传 + 金额格式** |
| xlsx 往返 | 单表 | **主表 + 子表两段**（往返契约要重新设计） |

> **结论**：报告单不是"再加一张模板"，而是**引擎长出一个新的表形态**。本期把它排除是对的划分；把边界预先写清，是为了让将来那一步有起点，而不是把它偷偷混进"统一"里。

### 3.5 汇总算法：三种算法 + 派生显示（不落库）

#### 三种算法（`weight_mode` × `track` 的组合）

| 算法 | 何时用 | 公式 | 素材依据 |
|---|---|---|---|
| **A1 加权求和（倍率）** | `weight_mode=multiplier`（**存量默认，行为不变**） | 行总分 `weighted_total = Σ(value × weight)` | 现状（[`EduAssessRoster._compute_derived`](../../custom_addons/edu_assess/models/assess.py)） |
| **A2 占比加权** | `weight_mode=percent` | 项贡献 `= (value / max_score) × weight_ratio × total`；行总分 `= Σ 项贡献` | xlsx `I = H × E` 且 `E27=SUM(E5:E26)=100%`（[§6.1](eval-materials-inventory.md#L289-L295)） |
| **A3 双轨平均** | 项 `track=dual` | **先**算该项目的分：`项分 = (客观 + 主观) / 2`，再进 A2/A1 | 说明 P052 原文 `(客观评分 + 主观评分) ÷ 2 × 百分比 = 子评分的总分`（[§2.3](eval-materials-inventory.md#L143)） |

> **A2 与素材公式的等价性（数值自证，不是类比）**：素材里 `F/G` 两列都是**百分制**（说明 P056 逐字：「其他类目子评分的分数范围均为 0-100 分（百分制）」，[§2.3](eval-materials-inventory.md#L144)），因此 `max_score = 100`、`value/100 = H/100`。取 `total = 100` 时 `(H/100) × E × 100 = H × E` —— **与 xlsx 的 `I5 = H5*E5+…` 逐字符同式**。**这意味着：用户手上那张 xlsx 的服务端复算结果会与 Excel 完全一致**（这是"录入进去"能被验收的唯一硬标准）。

> **接缝登记（2026-09-30，由 `docs/research/scoring-dual-track-and-deduction.md` §6.4 提供，队长已裁定）**：业界还存在**第四种合并语义** —— Canvas **Moderated Grading**：每位评分人各出一份临时成绩（`ModeratedGrading::ProvisionalGrade`），由主持人**选定其中一份**（或手写一份）作为最终分，并留 `create_moderation_event` 审计（源码 `app/models/moderated_grading/selection.rb`、`provisional_grade.rb`）。
> **本期不实现**：素材说明表 1 已把口径写死为「客观评分 + 主观评分 **各占 5%**」（等权相加）——**规格优先，不用别人的产品设计覆盖用户写下的口径**。
> **将来要加时的接缝**：① 项级合并**必须走算法枚举分派**（见 §5.5 N1「算法族固定为枚举」），**不得**在 xlsx 导出 / 结果页 / 报表里内联 `(a + b) / 2`；② `edu.assess.score.track` 已是行级标签，"选定"语义只需再加"哪条是最终分"的标记位，**不改唯一键**；③ "缺一路"判定与"选定"语义**共用同一处 `state` 计算**。

#### 分档与缺一路（**静默低估必须消除**）

- 单轨项：`项分 = 该轨的值`。
- 双轨项：`项分 = 两路均值`；**缺一路时**（盘点文档点名的 Excel 级脆弱：`H5=SUM(F5:G5)/2` 写死除 2，空 F 会静默低估一半，[§6.3](eval-materials-inventory.md#L347)）：
  - **默认**：该行 `state = 未评（pending）`，**不产生最终总分**，结果页显式标注「缺一路：客观/主观」；
  - 可选开关（模板级，**默认关闭**）：允许按**已填路数**平均，并在结果里留痕「按单路计」。 ⚠ **第 2 期只落地了"默认关闭"这一侧**（改用一个模块常量，**"可选"这一半没有实现**）⇒ 见 §5.3 的**实现偏差登记**。
  - **不采用"空当 0"** —— 那是素材里的缺陷，复刻它等于把 bug 抄进系统。
- **实现约束（2026-09-30 补，依据 `docs/research/scoring-dual-track-and-deduction.md` §6.4）**：A3 双轨合并**只允许有一个实现入口**；xlsx 导出、结果页渲染、打印报表**一律调用它**，禁止各自再写一次"两路相加除 2"。同理，任何跨模板/跨项的汇总都必须带上 `score_mode` 与 `track`（§5.4 已登记的同一风险）。Moodle 5.0 的做法可作参照：合并入口在 `aggregate_submission_grades_process()` 一处，出口与出口之外无第二份公式。

### 3.6 什么情况下才允许破例新增模型（给将来的自己一条明确线）

只有满足**全部三条**才新增：
1. Q1 判定为"新的多值依附表"（不是评分项、不是名单行、不是分组节点）；
2. 它承载的数据**字段结构稳定**（不会因为用户自定义而变表结构）；
3. 它**无法**用"既有行 + 枚举字段 + 派生计算"表达（必须写清为什么，并附一次调研）。

—— H6 报告单满足三条（将来若做）；本设计**其余全部缺口都不满足**，因此本期零新模型。

## §4 「自定义创建」的自定义边界表

> **本节是用户三个要求里最核心的一条**（原话 Q2「自定义创建」）。设计口径：**把"什么可以被用户改"写死成一张表**，而不是笼统地说"可配置"。每个维度只允许三种裁决值之一：
>
> | 裁决 | 含义 | 落地形态 |
> |---|---|---|
> | ✅ **可自定义** | 用户（教务）在界面上随时改，**不发版、不改 schema** | 数据行 / 普通字段（沿用 C 套「列即数据行」机制；`assess.py` 模块 docstring「评分项 = 数据行，列不是模型字段」） |
> | 🔒 **固定** | 由系统约定，用户不能改 | 枚举常量 / 服务端算法 |
> | 👁 **只读** | 系统**派生计算**出来的量，用户看得到但改不了 | compute 字段（用户若改了就会与来源冲突） |
>
> **三条边界原则**（后面每一行的裁决都能回溯到其中一条）：
> 1. **凡「结构」皆可自定义** —— 层级、项、分值、权重、刻度、角色、开关，都是"用户表达自己的表"的词汇。
> 2. **凡「算法族」固定为枚举** —— 只提供 3 种算法（双轨平均 / 加权 / 求和），**不做自由公式编辑器**（依据：盘点文档 [§12.2 N1](eval-materials-inventory.md#L679)——6 张表的公式**全都只有这 3 种模式，没有一处是用户自造公式**）。
> 3. **凡「派生量」只读** —— 小计 / 合计 / 占比合计 / 等级，一律服务端算，用户改不动（依据：C 套 `IGNORED_HEADERS` 的既有口径——「总分一律服务端算，防篡改」，[§9.4](eval-materials-inventory.md#L508)）。

> 每条给出：**要求什么（素材）→ 设计怎么做 → 落在哪些字段 → 谁来录 → 怎么证明做对了**。缺口的编号沿用 §2.2（H1–H6）。

### 5.0 一览

### 5.1 H1 —— 三层分类层级（G2）

**素材要求**：说明表 1 是「类别 → 子项目」两级；xlsx 是「一级分类 → 二级分类 → 三级」三级，且**权重挂在三级（叶子）上、父级只是汇总**（[§6.1](eval-materials-inventory.md#L320) 逐字：「权重挂在叶子（三级）上，父级只是汇总」）。

**设计**：给 `edu.assess.item` 加自引用 `parent_id` 与节点类型 `item_kind`：

| 概念 | 表达 | 约束 |
|---|---|---|
| 一级类别（综合技能） | `parent_id = 空` 且 `item_kind = group` | — |
| 二级子项目（生活技能） | `parent_id = 一级节点`，`group` | — |
| 三级项（时间管理 3%） | `parent_id = 二级节点`，`leaf` | **权重只允许挂在 `leaf` 上** |
| 深度上限 | ≤ 3 层 | 保存时校验：`parent.parent.parent` 存在即报错（**先例**：[downloads.py:30-34](../../custom_addons/edu_portal/models/downloads.py#L30-L34) 的两级深度约束同型） |
| 分组节点的满分 | **派生、只读**：= 子项 `max_score` 之和 | 一级节点的占比同样派生（§4 #8） |
| 分组节点不能被打分 | 填写页只为 `leaf` 渲染输入框 | 防止"给一个类别打一个总分"这种双重计分 |

**为什么限 3 级**：xlsx 的表头最多三层（[§6.1](eval-materials-inventory.md#L286) 的 22 个合并区就是三层的编码），而 §6 E6 的冻结表头要靠**固定层数**渲染；无上限的层级会让这两处同时塌掉。

**xlsx 侧**：导出时按层级生成**三层合并表头**；导入时按列名别名识别层级 —— 素材里同一列有两套名（`类别/项目` vs `一级分类/二级分类/三级`，[§8.2](eval-materials-inventory.md#L411)），因此需要一张**别名表**（固定，见 §4 #30）：`{类别, 一级分类} → 一级`、`{子项目, 二级分类} → 二级`、`{评分说明, 三级} → 三级`。

**验收证明**：建出 xlsx 范本的三级结构后，导出的表头合并区数与素材 `示范模版` 的层级部分一致；权重上卷（三级 → 二级）逐项等于说明表 1 的二级占比（[§8.1](eval-materials-inventory.md#L392) 的 8 行对账全部 OK）。

### 5.2 H2 —— 占比语义（G1）与小计（G4/W2）

#### 5.2.1 权重模式

| 模式 | `item.weight` 的读法 | 校验 | 适用 |
|---|---|---|---|
| `multiplier` 倍率（**存量默认**） | 得分放大倍数 | `weight > 0`（现状） | C 套现有 3 个模板 / 7 个项（全 `weight=1`，[§9.6](eval-materials-inventory.md#L561)） |
| `percent` 占比 | 该叶子项占总分的百分比 | `weight > 0` **且 Σ(所有叶子) = 100**（容差见下） | 说明表 1 / 表 4 / xlsx 范本 |

**Σ=100 的校验时机（必须写死，否则是空话）**：

- **可以保存草稿**（如 `state=draft` 的模板）：中途正在搭结构，强制 100 会让人无法中途保存；
- **启用（`state=active`）与创建任务前必须 Σ=100**：否则总分算出来不是 100 分制，而用户会以为它是 —— 这正是 xlsx 用 `E27=SUM(E5:E26)` 显式自校验防的事（[§6.1](eval-materials-inventory.md#L294)）；
- **容差**：占比用一位小数（素材里有 7.5%），因此按 `|Σ − 100| < 0.01` 判等，避免浮点误差误报。

#### 5.2.2 小计与合计（**派生、不落库**）

| 层 | 计算 | 展示位置 |
|---|---|---|
| 叶子项贡献 | `(value / max_score) × (weight / 100) × total`（占比模式） | 填写页/结果页 |
| 二级小计 | 该二级节点下**叶子贡献之和** | 结果页分组表尾 + xlsx 小计行 |
| 一级小计 | 其下二级小计之和（= 一级占比 × total，用于与说明表 1 对账） | 结果页 + xlsx |
| 总分 | 一级小计之和（倍率模式 = 现状 `weighted_total`） | `roster.weighted_total`（已有字段，**不新增**） |

#### 5.2.3 ⚠ 「学业表现」到底留空多少（**按素材精确化，与裁定表述有一处出入，显式记明**）

队在裁定 A7 写的是「「学业表现」那 7.5% 本期留空」。按素材逐字核对，**学业表现是两项各 7.5%、合计 15%**（[§2.2](eval-materials-inventory.md#L129)）：

| 项 | 占比 | 评分方式 | 本期处置 |
|---|---|---|---|
| 学术成果 | **7.5%** | **客观成绩**（依据《成绩统计表》） | ⛔ **留空 + 显式标注未实现**（该文件未提供，[§11-①](eval-materials-inventory.md#L646)） |
| 学习态度 | **7.5%** | **导师评定** | ✅ 正常可评（来源齐备，无需留空） |

**设计**（不编造任何分数来源）：模板里**照样建出「学术成果」这个叶子项**（占比 7.5%），但它被标记为「未实现」：

- 模板 `notes` 写明「学术成果（7.5%）的分数来源《成绩统计表》未提供，本期不可评」；
- 填写页/结果页显示**未评项清单**，并提示「本模板当前可评满分 92.5 分」；
- 该项**不参与**总分归一（不按 0 计入，也不把 92.5 当 100）——避免把"缺资料"伪装成"考得差"。

> **若队长的本意是整块 15% 都留空**，请纠正（§11 记一条），设计改动很小（把「学习态度」也标记未实现）。

### 5.3 H3 —— 客观/主观双轨（G3）

**素材要求（逐字）**：说明表 1 `子评分` 列「客观评分 + 主观评分 / 各占 5%」；说明表 2：客观评分 0–100「导师根据实际观察评分」、主观评分 0–100「学生自我评价」；算式 P052「(客观评分 + 主观评分) ÷ 2 × 百分比 = 子评分的总分」；xlsx `H = (F+G)/2`；**且只对技能类 12 项启用**（其余 10 项 `F` 列合并为「无」＝不设自评，[§6.1](eval-materials-inventory.md#L287)）。

**设计（四件事）**：

| # | 事 | 设计 |
|---|---|---|
| 1 | **哪一项分双轨** | 项级 `track ∈ {single, dual}`。素材的"类别级启用"用**同类项一起设**即可表达；反之做不到 ⇒ 项级是正确粒度 |
| 2 | **两路由谁填** | 任务级 `objective_scorer_kind` / `subjective_scorer_kind`，默认 = `teacher`（客观）/ `self`（主观），否则取任务的 `scorer_kind` |

> ⚠ **实现偏差登记①（2026-09-30；是"实现偏差"，不是"设计变更"）**：上表第 4 行的「**可选开关**（模板级，默认关）按已填路数平均」，第 2 期**未实现**。
> - **实际实现**：模块常量 [`ALLOW_PARTIAL_DUAL`](../../custom_addons/edu_assess/models/assess.py)（定义在 `assess.py` 模块级，实现方在模块 docstring「有意偏离设计文档的地方」一节自陈）；唯一读点是 [`EduAssessRoster._item_cell`](../../custom_addons/edu_assess/models/assess.py)（缺一路时，不放开就直接 `return None`）。⇒ 常量**只固定"默认关闭"这一侧**：算分行为与设计一致（缺一路 ⇒ 该项不计分、也不按单路平均），但**"可选"这一半没有落地** —— 用户改不了，也没有「按单路计」的留痕路径。

### 5.4 H4 —— 扣分制 + 同页多区段 + 分区小计（G5/G6/G7）

**素材事实（先说清它到底是什么表）**：`卫生检测表` = 5 个区域横向并列，每区「检查项列 + 评分列」；**每项扣分是写死的固定值**（−5/−3/−2/−1）；**每区各项扣分之和恰好等于区满分**（厨房 5+2+5+5+5+5+3 = 30，其余同；程序化核算见 [§8.4](eval-materials-inventory.md#L444)）；`A10 共计分数` + 5 个小计 + `A11 总分`；及格线 60。

**设计**：

| 概念 | 表达 |
|---|---|
| 区域（厨房 30 分） | **一级分组节点**（`item_kind=group`），其满分 **派生** = Σ 子项 `max_score`（正好 = 30/30/20/10/10 ⇒ 总分 100） |
| 检查项（洗碗池有污渍 −5） | **叶子项**，`score_mode=deduct`，**`max_score` 即"扣到底扣几分"**（= 5） |
| 录入形态 | **勾选式**：勾 = 全额扣（−5）；也允许把扣分改成更小的值（现实中会"部分扣"），始终钳在 `0 ≤ value ≤ max_score` |
| 单元格存什么 | `score.value` = **实际扣掉的分数**（0 = 未扣） |
| 项得分 | `max_score − value` |
| 分区小计（共计分数） | 区内叶子 `Σ(max_score − value)`（**派生**） |
| 总分 | 各分区小计之和（倍率模式 + 全部 `weight=1` ⇒ 纯求和，与素材一致：本表**无权重**，满分即权重，见 [§7.3](eval-materials-inventory.md#L385)） |
| 及格线 | **60**（素材唯一有据的阈值） |

**⚠ 必须讲清的取舍：版式是"语义等价 + 版式替代"**

- 引擎里的等价形态是**一张纵向矩阵**：行 = 被评者（学生/宿舍长），列 = 32 个检查项，按 5 个一级节点**分组渲染成 5 个区块**，每区块尾行给出小计。
- 素材那份是**5 段横向并列**（每段自带"项列 + 评分列"）。两者**信息与算式完全等价**（区域项数 7/7/6/6/6、区满分 30/30/20/10/10、分区小计、总分 100），但**纸面版式不同**。
- **不改版式的代价与理由**：素材那张表自己 §7.3 就写明「**结构上最需要冻结**」（10 列 × 13 行 + 5 区并列，[§7.3](eval-materials-inventory.md#L386)——两份 xlsx 的 `freeze_panes` 都是 `None`）；而"多区段横向并列"是要新建一套表格渲染范式（等于为一张表开一条渲染分支），与"一个引擎一套矩阵"的目标相反。
- ⇒ 本文采用**纵向矩阵 + 分区区块**；若用户要求纸面版式原样复刻，那是**另一条工作线**（§11 记一条拍板项）。

**评分方向的风险（登记 §10）**：同一张 `edu.assess.score` 表里，`value` 有两种读法（加分制=得分；扣分制=扣分），解释权完全在 `item.score_mode`。任何**跨模板/跨项**的汇总代码都必须带上 `score_mode` 与 `track` 才能算对。

### 6.1 E1 · E2 · E3 · E4 · E5（五条常规项；E1–E5 合并为本节，E6–E9 各占 §6.6–§6.9，节号与需求号对齐）

| 需求 | 设计 | 为什么这样 |
|---|---|---|
| **E1 列可增删改** | 沿用"评分项 = 数据行"（`assess.py` 模块 docstring）；本期只加一件事：**新建项时选父节点**（挂到一级/二级/顶层） | 已是全仓唯一达标项；有打分的项**拒删只可停用**的护栏也已存在（[`EduAssessItem._unlink_guard`](../../custom_addons/edu_assess/models/assess.py)），不得回退 |
| **E2 行可增删** | §5.7：加一行 / 删一行 / 批量粘贴名单 | xlsx 序号 1–14 就是数据行（[E2](eval-materials-inventory.md#L666)） |
| **E3 公式自动算** | §3.5 三种算法（倍率 / 占比 / 双轨平均）；占比模式的 `Σ=100` 就是素材里的 `E27` 自校验 | 6 张表**全都依赖公式**：xlsx 38 个公式含 `(F+G)/2`、`H*E`、`SUM`、`E27`（[§6.1](eval-materials-inventory.md#L289)） |
| **E4 小计 / 合计行** | 二级小计 / 一级小计 / 总分**全部派生**（不落库，§3.5）；呈现位置：① 结果页分组表尾 ② xlsx 导出的小计行与校验行 | xlsx `I5/I8/I11/I14` 是按二级组合并的小计、`I27` 总分、`E27` 占比校验（[§6.1](eval-materials-inventory.md#L292)）——三条都要复刻 |
| **E5 刻度即时校验** | §5.8：锚点 + `scale_rule`；标红沿用既有通道（[assess_grid.js:21-40](../../custom_addons/edu_assess/static/src/js/assess_grid.js#L21-L40)） | 说明 P067-073 给了 5 档锚点与中间值集合 |

> **⚠ E4 的一条明确取舍：填写页不做"实时小计"**
> Excel 里小计会随输入实时变；本设计**不在填写页实时算**，理由是**算法只能有一个来源**——前端再实现一遍加权/双轨/占比，就必然与后端漂移（这正是这个仓库反复吃过的亏：同一语义两处实现，改一处漏一处）。填写页只做"范围与刻度"这类**不需要算分**的即时反馈；小计在**提交后**的结果页与 xlsx 里呈现。
> 若将来确实要实时小计，正确做法是**把服务端算出的分带回填**（如保存后局部刷新），而不是在前端重写公式。

### 6.6 E6 —— 冻结表头（用户体感最核心之一，当前 0 实现）

**为什么必须做（不是锦上添花）**：xlsx 是 `A1:I27` 的 9 列 27 行；卫生检测表更是 `A1:J13` 的 **10 列 × 5 区并列**；盘点文档 [§7.3](eval-materials-inventory.md#L386) 逐字写它「**结构上最需要**（5 区 × 最多 7 行，横向很宽）」——而两份 xlsx 自己的 `freeze_panes` 都是 `None`，现有三套引擎的 `sticky/freeze` 实测命中 **0**（[§12.1 E6](eval-materials-inventory.md#L670)）。

**前端怎么做**（关键在"谁是滚动容器"）：

| 步骤 | 做法 | 坑（必须写进实现说明） |
|---|---|---|
| ① 滚动容器 | 给矩阵包一层容器：`max-height: calc(100vh - 220px); overflow: auto;`（数值按门户实际版式定） | `position: sticky` **只在最近的滚动祖先里生效**。若指望页面级滚动，表头会随页面滚走；若外层门户已有 `overflow` 也会让 sticky 失效 ⇒ **矩阵必须自己成为滚动容器** |
| ② 表头冻结 | `.yy-assess-matrix thead th { position: sticky; top: 0; z-index: 2; }` | ① `border-collapse: collapse` 下 sticky 行的边框会"掉线"⇒ 用 `box-shadow: inset 0 -1px 0 var(--border-control)` 补（仓内已有 `--border-control` 令牌，[color-system-v4.md](color-system-v4.md)）；② 背景色必须显式给（否则透明会透出下方内容） |
| ③ 首列冻结 | `.yy-assess-matrix td:first-child, th:first-child { position: sticky; left: 0; z-index: 1; }`，交叉格 `z-index: 3` | 首列（学号/姓名）横向滚动时必须可读 —— 32 列卫生表就靠它 |
| ④ **多行表头怎么冻** | **只冻结"叶子表头行"**（最靠近数据的那一行，即评分项名），上面的一级/二级分组行**随内容滚走** | 三层合并单元格做分层 sticky 需要给每层算 `top` 偏移，`rowspan/colspan` 混在一起时极易错位。**取舍写在明处**：先保证"列名永远可见"（教师整班录入真正需要的），不追求三层全冻 |
| ⑤ 打印时关掉 | `@media print { thead th, td:first-child { position: static; } }` | 打印时 sticky 会造成表头叠在内容上（§6.9） |

**数据怎么落**：**不落任何数据**。冻结是纯样式，不碰 `edu.assess.score`、不碰提交路径、不新增路由。

**与 `assess_grid.js` 的关系**：**无关，也不该塞进去**。该文件自陈"只做三件不改变数据语义的事"（[assess_grid.js:1-7](../../custom_addons/edu_assess/static/src/js/assess_grid.js#L1-L7)），冻结是**样式层**的事。落点：新增一个模块内样式文件（`edu_assess/static/src/css/assess_grid.css` 或 scss），并在 `__manifest__.py` 的 assets 里加一项（现有 JS 已在 `__manifest__.py:42` 的 bundle 中）。**改动面：模板容器 class + 1 个样式文件 + manifest 1 行。**

**怎么验证**：① `grep -c 'position: sticky' ` 从 0 变 ≥2（表头 + 首列）；② 浏览器实测：滚动 27 行矩阵时截图，表头可见；③ 横向滚动 32 列时首列可见；④ 打印预览里表头不重叠。

### 6.7 E7 —— Excel 整块粘贴（用户体感最核心之二，当前 0 实现）

**为什么必须做**：教师整班打分场景——"一列几十行是同一种给分"，而且用户手上本来就有 Excel（[§12.1 E7](eval-materials-inventory.md#L671)）。现状实测 `paste/onpaste` 命中 **0**，`assess_grid.js` 98 行里没有任何粘贴逻辑。

**设计（四段：怎么触发 → 怎么解析 → 怎么落 → 怎么提示）**

| 段 | 设计 |
|---|---|
| **① 触发** | 在矩阵容器上监听 `paste` 事件，**仅当焦点在 `.yy-assess-matrix input` 内**时接管（其余粘贴一律放行，不劫持页面） |
| **② 解析** | 取 `ev.clipboardData.getData('text/plain')`；Excel 复制出来就是 **TSV**（`\t` 分列、换行分行）；若只有 `text/html`（从网页表格复制）**本期不做 HTML 解析**（登记为不做，见 §10） |
| **③ 落点** | 以**当前焦点单元格**为锚点，向右/向下铺开；列键 = `(项, 轨)`（双轨项占两列，§5.3）；**超出矩阵范围的部分截断并提示**（不静默丢弃） |
| **④ 数据怎么落** | **零后端**：粘贴只是把值写进**既有的** `<input name="v_<roster_id>_<item_id>">`（矩阵的既有命名，[assess_portal.xml:196-215](../../custom_addons/edu_assess/views/assess_portal.xml#L196-L215)），提交仍走原来的表单 POST（`/assess/grade/<id>/save`）；服务端校验、幂等键、总分服务端算**全部不变** |

**值处理（对齐既有服务端口径，不另立一套）**：

| 输入 | 处理 | 依据 |
|---|---|---|
| 空单元格 | **跳过（不清库）** | 沿用 xlsx 导入的既有口径（空 = 跳过，[§9.4](eval-materials-inventory.md#L526)） |
| 非数字（含中文、全角符号） | **不写入** + 该格标红 + 计数提示 | 与 xlsx 导入"非数字整行不写入"同向，但粘贴是逐格，所以逐格拒绝 |
| 超满分 / 负值 | 写入 + 标红（提交时由既有 `clampAll` 夹取） | 既有通道（[assess_grid.js:32-40](../../custom_addons/edu_assess/static/src/js/assess_grid.js#L32-L40)） |
| 千分位/百分号/货币符号 | 去掉分隔符后按数字处理 | 用户从 Excel 复制常见 |

**与 `assess_grid.js` 的关系（明确回答）**：**扩展这个文件**（同一 IIFE 内加 `paste` 监听），不新开第二个脚本 —— 理由：矩阵的"焦点格 → 值 → 标红"三件基础设施都在这个文件里（`cells()` / `paint()` / `colIndex()` / `rowIndex()`），另开文件会重复实现并产生两套坐标系统。**必须保住**它自陈的"无 JS 也能提交"（渐进增强）：粘贴失败/浏览器不支持时，手工录入不受影响。

**顺带复用**：同一个 TSV 解析函数**复用到名单批量粘贴**（§5.7）—— 落点不同（一个是给 input 赋值，一个是提示预览后建 `roster` 行），但"TSV → 二维数组"这一步共用。

**怎么验证**：① 从 Excel 复制 5×3 块 → 粘到矩阵第 2 行第 3 列 → 断言 15 个 input 的值正确；② 越界块 → 出现截断提示且多出的值不落库；③ 含中文的格 → 标红且不写入；④ 粘贴后提交 → 服务端入库值与页面显示一致（**用 xlsx 导回核对**）。

### 6.10 明确不做（N1 / N2 / N3）

| # | 不做的东西 | 理由（逐字依据） |
|---|---|---|
| N1 | 自由公式编辑器 | 6 张表的公式**全都只有 3 种模式**（双轨平均 / 加权 / 求和），**没有一处是用户自造公式**（[§12.2](eval-materials-inventory.md#L679)）⇒ 把公式做成"三种可配置算法"即可 |

## §7 权限口径

> **前置口径**：本设计**不新增权限面、不缩权**。所有新字段的编辑权**跟随其所属模型**的既有 ACL（§7.2 表），因为「谁能动模板」这件事在 C 套里已经定死了，而且与仓内权限家族正本 [perm-model.md](perm-model.md)（「教务 ≠ 系统管理员」四层规范）一致。本节的价值不是"重新分配权限"，而是**把边界写下来**，避免实现时各人各理解。

### 7.1 权限的四层（与既有 ACL/行级规则逐条对应）

| 层 | Odoo 组 | 在评估引擎里的角色 | 依据 |
|---|---|---|---|
| 门户 | `base.group_portal` | 学生 / 家长：**只能看"本人是被评者"的行**，且只能看 `open` 任务 | [security.xml:28-48](../../custom_addons/edu_assess/security/security.xml#L28-L48) |
| 教师 | `openeducat_core.group_op_faculty` | 打分人之一；模板/项/任务**只读**，名单与打分**读+写+建**（受行级规则收敛到本人任教班） | [ir.model.access.csv:4,7,10,13,16](../../custom_addons/edu_assess/security/ir.model.access.csv#L4) |
| 教务 | `openeducat_core.group_op_back_office_admin` | **模板与任务的全权**（建/改/删/归档、建任务、导出导入） | 同上 CSV 的 `_admin` 行 |
| 系统 | `base.group_system` | 与教务同权 + 后台配置 | 同上 CSV 的 `_system` 行 |

**两条既有设计要点（本文不得回退）**：

1. **门户组与内部用户组在 ACL 上一行都不给**（`0,0,0,0`）—— 所以门户要走控制器而不是 `call_kw`（[security.xml:9-12](../../custom_addons/edu_assess/security/security.xml#L9-L12)）；
2. **教务/系统有显式"恒真域"规则** —— 因为 Odoo 规则组合是「同组内 AND、跨组 OR」，缺了它，一个既在教师组又在教务组的人会被误收敛成"只看自己任教班"（[security.xml:23-25](../../custom_addons/edu_assess/security/security.xml#L23-L25)）。

### 7.3 学生自评与导师评：先后与可见性

**素材给了什么**：说明 P021 逐字只写了「合一性：**学生与导师共同参与评分**，鼓励双向沟通与属灵同行」；**未规定先后，也未规定可见性**（[§2.1](eval-materials-inventory.md#L103)）。⇒ 这是本设计**新增的口径**（登记在 §10），不是从素材抄来的。

| 问题 | 本期口径 | 理由 / 可调性 |
|---|---|---|
| 谁先填 | **不强制先后**：两路各自独立填，任一时刻都可提交 | 素材未规定；强制先后会让"导师忙没空"卡住学生 |
| 需要先后怎么办 | **用既有字段实现，零新字段**：任务的 `date_begin/date_due` + 两个任务的先后关系（例如"导师评"先开、"学生自评"后开），或教务决定开放时机 | 既有 `date_begin/date_due` 已足够表达时间窗（[`EduAssessTask.date_begin`](../../custom_addons/edu_assess/models/assess.py) / [`EduAssessTask.date_due`](../../custom_addons/edu_assess/models/assess.py)） |
| 填的时候能不能看到对方的分 | **默认互不可见**（背靠背）；**双方都提交后**（或任务关闭后）按 `score_visible` 展示 | 防锚定：看到导师给了 40 再自评，自评分就不再是独立信号 |

## §8 迁移与清理

### 8.0 铁律：**不动用户已有数据**

> 本设计的任何一步，**都不删除、不改写、不重命名**任何一条现有评估数据。所有新增字段**全部带默认值**，因此存量记录在新代码下的**语义与算分与升级前完全一致**。

#### 8.0.1 本节为什么不再写死数字（2026-09-28 改法）

本节原来有一列「现状（本地 `edu19` 实测）」，逐字写着**模板 3 / 评分项 7 / 任务 3 / 名单 7 / 打分 8**。**这五个数字一直在动** —— 还有 agent 在并行造验收夹具，跑一次冒烟就会变。本仓实测：同一套命令在两个时刻读出过两组**不同**的数（`3/7/3/10/8` 与 `3/7/4/12/11`），而文档里那组 `3/7/3/7/8` 是**更早的第三个快照**。

⇒ **写死读数和写死行号是同一个病**：把「某一刻的状态」当成「恒真的事实」写进文档。本节因此只保留**口径 + 复核方法**；任何数字**必须连采集时刻一起抄**，没有时刻的读数一律当**未采证的传闻**。

**每张表的计数口径**（复跑必须按同一口径，否则两次读数不可比）：

| 表 | 计数口径 | 数字里的坑（不写清就会对不上号） |
|---|---|---|
| `edu.assess.template` | `count(*)`，**不筛 `active`** | `active`（启用）与 `state`（draft/active/archived）是**两个维度**，别混；停用的模板照样占一行 |
| `edu.assess.item` | `count(*)`，**不筛 `active`**；**含 `item_kind='group'` 的分组节点** | 第 2 期起「评分项」= 节点：叶子才是可打分的一列，分组节点只做分类与小计。**只数叶子**会与第 1 期读数差一截 |
| `edu.assess.task` | `count(*)`，**不筛 `active`、不筛 `state`** | 任务同样有 `active` 与 `state` 两层 |
| `edu.assess.roster` | `count(*)`，**不筛 `state`** | `roster` **没有 `active` 列**（§5.7 已登记）⇒ 不存在「只数在用行」这种口径；要分状态请另加 `FILTER` |
| `edu.assess.score` | `count(*)`；**双轨项一行两轨都算** | 双轨落地后，同一 `(名单行, 评分项)` 可存 **2 条**（`track=objective/subjective`）⇒「打分条数」**≠**「已评单元格数」。要数单元格得按 `(roster_id, item_id)` 去重 |
| 演示数据 | A / B 套的【演示】行**照数，不剔除** | 剔除会让读数不可复现。要单独看演示，**另加一列**，不要改口径 |

#### 8.0.3 引用纪律（本次同时立的规矩，适用于文档与代码注释）

**背景**：本文原有 39 行 `assess.py:NNN` 引用。其中按 **507 行版本**写的那一批**已全部失效** —— 该文件第 2 期后是 **1517** 行，同一批行号现在指向别的符号。**注意：它们当时大多是对的**（例：`scripts/check_view_xpath.py` 注释里的 `models/assess.py:490`，在 507 行版本里 `class ResUsers` 正好在 489–491 ⇒ 引用正确；第 2 期后 `ResUsers` 挪到 1499，第 490 行变成 `parent_id` 的 help 字符串）⇒ **连当时写对的引用都会烂，这才是问题的性质**：行号不是可维护的引用形式，逐条补对下次还会烂。

> **另有一类更糟的（本次回读 `git show HEAD:` 的 507 行版本时才发现）**：本文 §4.4 #31 原引的 `assess.py:253-260`（声称是 `init()` 里的 `DROP CONSTRAINT`）**在写下时就指错了** —— 那 8 行是 `EduAssessTask._check_summary_min`，而**那个版本里根本没有 `init()`**。这类错用符号名引用会当场暴露（`--grep init` 直接查不到）。逐条订正见 §4.4 表后第 3 条。

**规矩（三条）**：

1. **正文里的 `xxx.py:NNN` 一律改成「文件 + 符号名」**（例：`assess.py` 的 `EduAssessRoster._item_cell`）。符号名是**可复核的键** —— 读者当场跑一条命令就能拿到现行行号，不必信文档里的任何数字。
2. **行号只允许出现在显式标注了取证时刻的取证块里**，且必须写明「这是取证时刻的读数，不得据此定位代码」。带日期的历史取证块（"当时读到的代码长这样"）**保留** —— 那是证据，不是引用。
3. **写死的读数同罪**：任何「现状 = N 条」都必须带**采集时刻 + 可复跑的复核命令**（理由见 §8.0.1）。

**复核工具**：`python3 scripts/assess_symbol_index.py` —— `custom_addons/edu_assess/models/assess.py` 的「符号 → 现行行号」索引；`--grep <符号>` 单查，`--kind <类别>` 过滤，`--selftest` 自证。它自带三条自证：**符号总数不低于下限**、**六个模型类齐全**、**抽查 4 个已知符号与 `grep -n` 实测逐条一致**；**查不到符号、解析出 0 个符号、文件不存在一律非零退出**（不许静默成功）。

**⚠ 一处与既有调研结论的"有意偏离"（必须写明，不能装作没看见）**：

- 既有调研给的首选是「**权重靠分值表达，不引入单独 `weight` 字段**」（抄 Moodle：0/2/4/6 即两倍影响，[evaluation-rebuild.md](../research/evaluation-rebuild.md) 行 561）。
- 本期却**要引入 `weight_mode=percent`（占比）**。**理由**：素材要的是 `Σ占比 = 100%` 的**显式自校验**（xlsx `E27=SUM(E5:E26)`），而"满分"与"占比"在这几张表里是**两个独立维度**（三级项满分是百分制 0–100，占比是 3%/5%/7.5%）——"用分值表达权重"表达不出 `Σ=100%` 这件事。
- ⇒ 这是**有意的偏离**，不是矛盾：Moodle 的结论用于"权重可以不独立存在"的一般情形，而本素材**要求占比可校验**。**代价**：多一个模式字段与一套校验（已计入 §3.3）。
