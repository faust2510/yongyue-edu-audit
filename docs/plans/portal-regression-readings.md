## 2. 判据设计（为什么是这三层）

门户的取数判据是控制器里的 `current_student()` / `current_faculty()` / `current_parent()` / `privileged_staff()`
（`custom_addons/edu_portal/controllers/roles.py:150-176`），**与后台 ACL/菜单不是同一条通路**。
但「理论上不受影响」不是证据 —— 所以每页都按三层判据量：

| 判据 | 内容 | 防的是什么 |
|---|---|---|
| ① HTTP | 状态码 200 且**响应体无 Traceback** | 页面打不开 / 500 |
| ② 关键元素 | **渲染出的可见文本**（已剥 script/style/注释/标签）命中该页专属关键元素 ≥2 项 | 「200 但空白/报错」的假绿 |
| ③ 身份 | 页面上出现**登录者本人的显示名**（经 `res.users.read` 自读取得，**不写死演示名**） | 页面被打开但**取错身份的数据**（空壳页 / 串号） |

另有第四、第五组：

- **④ 越权负例**：学生/家长打教师页必须 `303 → /my/home`，且**拒绝响应里不含该页关键元素**（防「200 换个马甲」）；
  家长的 `/my/child/<id>` 只对**本人孩子**开放。
- **⑤ 后台判据**：见 §5。

**防假红的两条纪律**（本仓 doctrine：假红与假绿一样消耗信任）：

1. 关键元素一律取**模板里的裸文案**，并逐条核到 `.xml` 行号（见脚本 PAGES 表内注释）；要求「**≥2 项命中**」，
   因为少数块带 `t-if`（数据为空即不渲染），单点字符串会变成随机红。例：
   `batch2.xml:859` 的「待办提醒」整块 `t-if="approval_alerts"`、
   `batch2.xml:921` 的「今日我教的课」`t-if="today_classes['items']"`。
2. 身份名从会话自读，不写死「王小明」。

**脚本自身的可信度**（不是「跑绿就算赢」）：

| 自检 | 做法 | 结果 |
|---|---|---|
| 可重跑 | 连跑多次（含契约修订、补断言与正对照后） | **101/101**、exit 0，读数一致 |
| 防假绿闸门 | 用错口令跑（0 断言） | **exit 1** 并打印「未产生任何断言 → 判失败，不得视为通过」 |
| 前置探活分离 | 指向不可达端口 | **exit 2**（环境问题不伪装成断言失败） |
| 断言是否吃劲（变异测试） | 把一页的期望标题故意改错后跑 | **93 PASS / 1 FAIL、exit 1** ⇒ 退出码真的由断言驱动 |

副作用：**零**。全部是 GET / 只读 RPC（`has_group`、`read`），不建夹具、不写库、无 leftover，可并发跑。
