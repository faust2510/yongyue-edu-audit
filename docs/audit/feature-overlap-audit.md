## 1. 重叠清单（四层证据：模型 / 菜单 id / 数据 / 门户路由）

### 1.1 【真重复】学生打卡 —— 两套实现、两个门户页同时在线

| | A 套：灵命生活（`edu_life`） | B 套：日常管理（`edu_portal`） |
|---|---|---|
| 模型 | `edu.checkin.record`(36) + `edu.checkin.type`(3：读经/灵修/周记) | `edu.daily.checkin`(7：到堂/灵修/读经 三个布尔字段) |
| 菜单 | **593 灵命生活** → 594 打卡类型 / 595 打卡记录 / 596 周记归档 | **543 日常管理** → 544 全员打卡（+545 积分流水 / 546 教师积分排行） |
| 门户 | `/my/checkins`（月历+一键打卡+连续天数+导出）、教师 `/checkins/stats`、`/checkins/stats/export` | `/my/checkin`（**少一个 s**）、`/my/checkin/save`、`/my/checkin/board`（全员到堂看板）、`/my/checkin/export` |
| 实测 | 两页均 HTTP 200（学生账号可同时打开） | 全仓唯一写入口：`welfare.py:my_checkin_save` |

**判定**：真重复。两套维度是**并集关系**（A=读经/灵修/周记，B=到堂/灵修/读经）⇒ 合并后应为 **到堂 + 读经 + 灵修 + 周记**。

### 1.2 【引擎重复 + 口径不同】评估 —— 两套

| | 综合评估（`edu_portal`） | 行政评估（`edu_eval`） |

| 模型 | `edu.eval.template`(3) / `.template.line` / `.task`(1) / `.score`(5) | `edu.admin.eval.template`(0) / `.item`(0) / `.score`(0) |
| 菜单 | 588 综合评估 → 589 模板管理 / 590 评估任务 | 597 行政评估 → 598 评估模板 / 599 打分记录 / 600 结果分析 |
| 门户 | `/my/evaluation`（Excel 式整表打分 + 雷达图） | `/eval/my`、`/eval/fill/<id>`、`/eval/review`、`/eval/review/<id>/submit` |

## 2. 收口方案

### 2.1 打卡（t5 + t9）——并成一套

- **留** `edu_life` 那套（数据 36:7、有类型字典、有教师统计与导出、周记同模块），**并**入另一套的独有维度。
- 新增类型「**到堂打卡**」（daily、sequence=5、**不带【演示】**、get-or-create 幂等）。
- 迁移 7 条：内容零丢失；同 (学生,日期,类型) 已存在则跳过并记账；**目标 note 非空不覆盖**。
- note 合并：`devotion_note`→【灵修笔记】、`bible_passage`→【读经范围】、`bible_note`→【读经笔记】，`\n` 连接、空列不写。
- 路由：`/my/checkin*` → 303 `/my/checkins*`；`/my/checkin/board` **保留 200**、数据源改读新表（到堂类型）；模板「返回我的打卡」链接改指 `/my/checkins`。
- 已知副作用（**已认账**）：教师 `/checkins/stats` 多一列「到堂」，且 `avg_rate = sum(rates)/len(rates)`（`life.py:533`）覆盖所有 active 类型 ⇒ **平均完成率与排序会变**；学生门户多一张卡。
- 回滚：`--rollback` 只删台账内本次产生的记录；类型用 `active=False`；**旧表/旧模型/ACL/后端视图/action 一律保留**。
- 验收：新增 7 条到堂 + 回填 ≤5 + 零删除 + 到堂零跳过；幂等复跑 0 新增；rollback 实测；教师统计前后对照表。

### 2.2 菜单（t2）

- 目标：B(教务) ≤12、B(管理员) ≤20；对照表写明口径 A/B 与四角色实测数。
- 手段：只改 `active / groups / parent_id / sequence`；**禁止 delete**；脚本幂等 + `--dry-run` + `--rollback`；改动须在 `-u` 升级后仍生效。
- 隐藏判定（队长裁定）：以 `base.group_system` 为唯一「全可见」锚点；原生噪音只对超管可见；现有组 87「后台·完整视图」只用于「教师 vs 教务」分野；**不新建自定义组**。
- **改名（可选）**：菜单名来自基座 XML，直接改库会被 `-u` 还原 ⇒ 若要改名，必须由**我方模块**（如 `edu_nav`）用 `<record id="<基座 xmlid>" model="ir.ui.menu">` 覆盖，否则保持原名。
- 施工图见 §3。

### 2.3 评估 / 岗位（t4 设计，本轮不动数据）

- 评估：先把 588 / 597 **并到一个根**；引擎合并设计须给出「留哪套 + 统一模型 + 6 种口径承载 + 匿名评教不落身份 + 迁移 / 回滚」。
- 岗位：3 条校友岗位 + 25 份申请的合并方向与兼容；门户 URL 重定向策略。

### 2.4 原生噪音（t2 一并处理）

- **收窄到超管保留**：员工 196（有 2 条数据）、应用 15、设置 1。
- 其余见 §3 施工图。

### 2.5 防复发（t6）
