## 3.6 重名子项裁定（队长裁定②的落地）

规则：两个 action 的 `res_model + domain + context` **等价** → 保留一个（优先中文名规范、被更多角色引用的），另一个 `active=False`；**不等价** → 两个都留并写明差异。

实测范围：257(学生信息) 与 278(学生) 两棵树共 **36 个节点**。逐模型核对结果：

| 模型 | 菜单数 | 结论 |
|---|---|---|
| op.student | 2 | **等价**：258「学生」/ 279「档案」action 不同但 `domain=[]`、`context={}`、`view_mode` 完全一致 |
| res.config.settings | 2 | **等价**：272「设置」/ 284「设置」**同一个 action**（仅 groups 不同） |
| 其余 15 个模型 | 各 1 | 唯一，无可合并项 |

裁定：

- **258 保留、279 停用**（279 的 action 与 258 等价，且 258 位于容器 257 下、名称更规范）
- **272 保留、284 停用**（同一个 action；272 的 groups=[base.group_system]，与档2 口径一致）
- 另有 2 个**空容器**（270 活动管理、271 报告：无 action 且无子项）→ 合并后是空壳，一并停用

> 口径说明：此前"学生/教师/课程/班级/科目/课程详情 各两份"的说法在**本机数据上不成立** —— 两棵树里叫「学生」的只有 258 一个、叫「课程」的只有 263 一个（另一棵树下是「档案/院系/科目注册/学生课程详情」，名字不同、且除 op.student 外模型也不同）。因此按"等价才合并"的规则，实际只有上述 2 组 + 2 个空容器。
