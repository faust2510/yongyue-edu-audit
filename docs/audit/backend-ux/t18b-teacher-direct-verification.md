### 3.1 写入路径的收敛（比「下拉里没有」更硬的判据）

「下拉里没有」只能证明前端过滤；真正的越权面是 **POST**。我直接构造了一条越权 POST：

```
教师 POST m_5_36 = 77   （batch 8；subject 36「写作课程」**不是**他任教的科）
  -> HTTP 303 /grade-entry?batch_id=8&term_id=1&**saved=0**
  该科目库内读数:  61 -> 61        （未变）
  edu_grade_history 行数: 231 -> 231（无新留痕）
```

⇒ **服务端丢弃了越权格子**，与 `grade_entry.py` docstring 的承诺一致（「POST 里的 batch_id / subject_id /
学生 id 一律不信任」）。这是本卡范围收敛的**决定性证据**。

### 3.2 ⚠ 由此暴露的一个真缺陷（**只报不改**，见 §5）

同一次取证里我注意到：教师 batch 8 的网格共 **14 个科目列**，而他只任教其中 **4 个**。
行是按班收敛的，**列不是按任教收敛的**（`_columns()` 取的是「本班科目 ∪ 名单学生已报科目」）。
后果：教师**看得见 10 个自己存不进去的输入框**；填了之后保存 → `saved=0` →
**页面没有任何提示**（既不报错也不说「已忽略」），输入的值也不回显 ⇒ 从用户视角看是「我填了，没反应」。

（教务不受影响：那 14 列他全都能存。）

## 6. 未修的缺陷与建议（写作用域外 / 需拍板）

1. **§3.2 的「看得见、存不了、不报错」**：修法是让 `_columns()` 在 `pairs is not None` 时按任教科目过滤，
   **或**在保存被丢弃时给出「N 格越权已忽略」的提示。前者改的是**共享引擎**（会同时影响教务视图，
   而教务那 14 列是合法的），后者只改提示。**两种都不在本卡的「只做分流」范围内，故只报不改。**
