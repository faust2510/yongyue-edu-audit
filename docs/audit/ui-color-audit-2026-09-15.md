## 0. 一句话结论

**全站实测出现 53 种不同颜色，只有 22 种属于我们的设计令牌。** 剩下 31 种分成三族互不让步：

| 族 | 代表色 | 来源 | 状态 |
|---|---|---|---|
| **A 旧站金色学院风（暖）** | `#C8A870` 金 · `#FFFDF9` 暖白 · `#171512` 暖黑 | 旧站 `covenant.css`（见 `docs/yongyue-rebrand.md:10`） | **是品牌资产，却没进令牌层** —— 以字面值散落在首页/页脚/brand.css |
| **B B11 蓝绿工作台（冷）** | `#0E7BF2` · `#0C6DD7` · `#0F9B91` · `#5E6779` | `custom_home.css:83-139` 令牌层（带 t111/t112 对比度修订） | 有令牌、有对比度记录，但**没被执行到底** |
| **C Odoo / Bootstrap 出厂残留** | `#026DDE` · `#0F34C3` · `#714B67` · `#28A745` · `#DEE2E6` · `#767676` | Odoo 网站色板 + Bootstrap 5 + 浏览器 UA | **应该被消灭的**，却占了大头 |

**"不太和谐"的精确位置**：**门户工作台页面同时渲染了 A 和 B** ——
`/my/home`（教师工作台）上，冷灰正文 `#5E6779` 旁边就是金色链接 `#C8A870`，页脚又是一整块暖黑 `#12100E` + 暖米字 `#D9D2C5`，
紧挨着的是冷蓝按钮 `#0C6DD7`。一个屏幕上两种色温、两种字体（Roboto 无衬线 vs Noto Serif SC 衬线）。

## 2. 根因：三层 CSS 各管一段，互不知道对方

### 根因 ①：Odoo 网站色板从未自定义过（影响面最大、修起来最省事）

```
--color-palettes-name: 'base-1'
--has-customized-colors: 'false'      ← 关键：出厂色板当品牌色用了
--o-color-1: #026dde                  ← 首页按钮蓝
--o-color-3: #f3f2f2                  ← 校历页 98 处底色 rgb(243,242,242) 的来源
--o-color-5: #111827                  ← 页脚/深色块
--o-cc3-bg: #09417e                   ← 校历页深蓝
--link-color: #0f34c3                 ← 全站链接色
--form-valid-border-color: #28a745    ← Bootstrap 原生绿
```

**网站色板独立于后台品牌变量**：`/odoo` 里 `--primary-rgb: 14, 123, 242`，官网上是 `--primary-rgb: 2, 109, 222`。
`backend_variables.scss` 改的是后台，**管不到这里**。

### 根因 ②：令牌层存在，但没被执行到底

`custom_addons/edu_portal/static/src/css/custom_home.css:83-139` 是一份**质量很高**的令牌表
（带 t111「状态色压暗到 4.5 档」、t112「`--bs-primary` 惰性，必须接线到规则级」的修订记录）。但是：

- `--border:#E3E9F2` ↔ 实测边框 `#E7E9F2`（**92 处硬编码**，同一语义两个值）
- `--text-disabled:#B7C0CE` ↔ 实测 `#B6B0B0`（报名页 18 处，**Δ47，不在令牌内**）
- 令牌注释已判定 `#1FA971/#E8930C/#E5484D` 白底不达标（3.01/2.44/3.91）并换成新值，
  但 **`backend_b11.css:40-45` 仍原样硬编码着这三个旧值**。

### 根因 ③：后台 b11 只覆盖了一部分，残留比想象的多

后台 `/odoo/contacts` 实测仍有：

| 实测 | 含义 | 位置 |
|---|---|---|
| `#71639E` | **Odoo 社区版原厂紫** | `button.o-dropdown.dropdown-toggle`（导航栏） |
| `#714B67` | **Odoo 官方主色** | `a` 元素背景 |
| `#28A745` | Bootstrap 原生绿 | `span.o-mail-MessagingMenu-counter.badge`（消息角标） |
| `#DEE2E6` | Bootstrap 原生边框（23 处） | 列表/表格 |
| `#212529` | Bootstrap 原生正文冷黑（**全站 62 处**） | 后台 + 门户 |
| `#000000` | 纯黑（81 处） | 后台 |
| `--success:#28a745 --danger:#dc3545 --warning:#ffac00` | **Bootstrap 5 出厂状态色**，与令牌的 `#127A50/#C0272D/#E8930C` 是两套 | 后台根变量 |

`backend_variables.scss` 顶部注释写着"官方 primary_variables.scss 把按钮/激活态做成 map 快照…必须直接重做合并这些快照 map"——
**实测说明这条路只走通了一部分**（导航栏 `.o_main_navbar` 确实是 `#0E7BF2`，但下拉按钮仍是紫的）。

### 根因 ④：报名页的表单控件根本没被主题化

`/apply` 实测边框 `#767676` ×31 —— 这是 **Chrome 浏览器 UA 默认的 input 边框色**，
说明表单控件没有任何皮肤；同页还有 `#B6B0B0` 浅灰文字 ×18（白底对比度 **2.14**）和
`.badge` 白底白字（`bg #FEFEFE` + `fg #B6B0B0`，几乎不可见）。

## 4. 统一方案：两条路线（需要拍板）

"不和谐"的根因不是某个色值写错，而是 **A / B 两套设计语言同时存在**。
先定方向，再谈改法；否则改一轮还会歪。

### 路线 A（我建议）：**蓝绿工作台为唯一色板，金色降为"点缀令牌"**

- 令牌层（B）作为唯一事实来源，全站 53 色收敛到 ≈28 色
- 金色 `#C8A870` 保留但**只用于**：校徽/分隔线/荣誉标记/页脚题签，不允许作正文或链接
- 官网首页从"暖金学院风"改为"冷蓝学院风"（保留衬线中文标题作为气质，去掉暖底色）
- 理由：门户/后台是**高频工作界面**（教务每天用），工作界面用蓝绿是钉钉/企微验证过的惯例；
  且 `docs/plans/ui-reference.md` 的 B11 规范、`custom_home.css` 的 t111/t112 对比度修订都已经是这条路
- 成本：官网首页/页脚需要重做视觉；改动集中（令牌 + 网站色板 + b11 同步）

### 路线 B：**金色学院风统一全站**

- 把暖色升格为令牌（`--gold-500: #C8A870`、暖中性色阶），把冷灰冷蓝全部换掉
- 门槛：金色 `#C8A870` 白底对比度只有 **2.26**，作正文/链接**必须**加深到 `#836A42`（对比度 6.0+）
  或改为深底金字（页脚已经是 `12.63`，合格）
- 理由：官网首页的学院气质确实更"像学校"
- 成本：**大于路线 A** —— 门户 + 后台 5000+ 行 CSS 全部要重新校色，且后台是 Odoo 原生结构，
  暖色系与 Odoo 的冷色组件（表格/看板）天然冲突更多

### 无论走哪条，下面三件事都必须做（与方向无关）

1. **接上 Odoo 网站色板**（根因①）：`--has-customized-colors: false` → 设为品牌蓝族，
   一处改动全站公开页生效，`#026DDE/#0F34C3/#F3F2F2/#111827` 四个 alien 色一次性消灭
2. **后台状态色同步**（根因②③）：把 `backend_b11.css` 的 `#1FA971/#E8930C/#E5484D` 换成令牌新值，
   消灭残留紫 `#71639E/#714B67` 与 Bootstrap 原生绿 `#28A745`
3. **报名页表单补皮肤**（根因④）：`#767676` UA 边框 + `#B6B0B0` 浅灰字 是最容易被家长看到的页面

## 7. 口径冻结与已知修正（2026-09-15 二次核校）

> 由 t9 验证员与 t10 评审员对基线独立复算后驱动。原始取色数据无误，问题在文档与口径。

### 7.1 已修正的誊写错误（4 处）
§1 表 16 格中 4 格与归档原始 JSON 不符，已按原始数据改正：
`/` 链接色 10→**8**、`/apply` 链接色 5→**6**、`/my/home` 边框色 6→**7**、`/odoo/contacts` 底色 10→**9**。
（text 列 4/4 全对 ⇒ 属表格誊写漂移，非抓取差异。）

### 7.2 基线补齐：4 页 → 6 页
`/my/calendar?view=week`（text 12 / bg 19 / border 9 / anchor 9）与 `/odoo`→`/apps`（4 / 4 / 3 / 3）
已按同一 schema 补抓并写回 `ui-color-raw-2026-09-15.json`。「令牌外色为 0 的页面 6/6」自此可打分。

### 7.3 计数口径（冻结；before/after 必须同一支量具）
- **页面集合**：`/`、`/apply`、`/my/home`、`/my/calendar?view=week`、`/odoo`(→/apps)、`/odoo/contacts`
- **属性**：`text` / `bg` / `border` / `anchor` 四列，逐元素 computed 值去重计数
- **归一**：`rgba(r,g,b,a)` → `rgb(r,g,b)`（合并 alpha 变体）
- **剔除**：纯白 `rgb(255,255,255)`、纯黑 `rgb(0,0,0)`
- 按此口径实算 = **53**；同数据不剔黑白为 70、只算 text 为 30 —— 口径不绑定则指标不可比
- **主判据：令牌外色 = 0（口径无关）**；`53 → ≤28` 作辅助指标（**注**：53 只对最初四页成立，六页口径见 §7.7 —— 生产 69 / 本地 87）

### 7.4 「令牌内 22 / 令牌外 31」的判定规则此前未固化（已知缺陷）
该切分来自审计脚本中**手工维护的色表**（含 `covenant-gold` 等），不是机械提取，故不可机检、不构成唯一规则。
**修正**：令牌集一律以 `scripts/color_tokens.json`（由 t3 从唯一令牌源机械提取）为唯一输入；
在它落地前，任何「令牌外色」判定都不得作为验收结论。

### 7.5 环境口径
生产基线（本文件）用于**发布后**对照；改动的达标判据用**本地 before / 本地 after**同环境对照（本地 before 由 t12 归档）。
禁止「本地 after vs 生产 before」跨环境比较。

### 7.6 二次核校新增发现（源码侧，超出浏览器取色范围）
- `custom_addons` 内共 **206 个不同 16 进制色值，散在 27 个文件**，其中 **15 个非 CSS 文件**：
